# Day10 개념 지도 디자인

## 1. 기준과 목적
[새싹 과정 공통 DESIGN.md](../../../DESIGN.md)를 적용한다. 수강생이 Day10 개념의 **위치와 쓰임**을 한 장의 지도로 먼저 파악하는 거시적 학습 문서. 개념 설명은 지도의 보조 층으로 둔다. 사용자 지정에 따라 지도 영역은 공통 최대 너비(1120px)보다 넓은 1440px까지 사용한다.

## 2. 색상
공통 PDF 토큰: primary #142849, heading #1C2B40, text #222F44, muted #52667E, canvas #F9FBFE, surface #FFFFFF, soft #F0F6FD, border #D8E4F2, code-bg #1B2435, code-text #FFFFFF.

Day10 PDF에서 새로 추출한 토큰 (`Day10_Optimizer_Regularization_20261030_v2.pdf` p.3 “전체 지도에서 오늘의 위치”를 200dpi로 렌더링해 픽셀 빈도로 확인):

| 토큰 | 값 | PDF 용도 | HTML 용도 |
|---|---|---|---|
| `--layer-1` | #F0F6FD | 1층 상자 (AI 서비스) | 실험 한 번 |
| `--layer-2` | #E9F5EC | 2층 상자 (예측 모델 개발) | Epoch 반복 |
| `--layer-3` | #FBF2DF | 3층 상자 (학습·검증 실험) | Batch 한 번 |
| `--layer-4` | #1C2B40 | 4층 상자 (Batch 계산과 갱신) | 모델 내부 |
| `--color-accent` | #4B74A6 | 오른쪽 소제목 | 소제목·목적 표시. 흰 배경 대비 약 4.8:1 |

모델 내부 상자 안의 보조 글자 #E3EBF5·#BFD0E6은 어두운 면(#1C2B40) 위 가독성을 위한 파생값.

## 3. 글자
공통 기준과 같음. 개념 칩 이름 16px/700, 쓰임 설명 14px, 목적 표시 14px/700 accent.

## 4. 레이아웃
- 본문 1120px, 지도 구역만 1440px.
- 지도는 PDF p.3의 겹친 상자를 코드 구조(실험 → Epoch → Batch → 모델 내부)로 확장. 바깥일수록 드물게, 안쪽일수록 자주 실행됨을 반복 횟수 배지로 표시.
- Batch 흐름은 3열(예측 단계는 전체 폭), Epoch 끝 흐름은 1360px 초과 5열 → 3열 → 1열. 모바일에서는 화살표를 ↓로 바꿈.

## 5. 반복 패턴
- 개념 칩: 이름 · 그 자리에서 하는 일 · 목적 번호(①손실 ②최적화 ③일반화 ④측정·선택). 굵은 테두리는 실험표의 핵심 손잡이·판단 근거.
- 목적 번호의 뜻은 “목적별 보기” 버튼 이름이 범례 역할을 함. 색만으로 구분하지 않고 번호와 글자를 함께 표시.
- 같은 내용을 여러 구역에 반복하지 않는다. 목적 구분은 지도의 번호와 “목적별 보기”가 맡고, “좋은 해” 구역은 그림과 설명 3줄만 둔다. 코드 골격에는 상자 경계 주석만 둔다.

- 구성: 머리말 → 개념 지도 → 코드로 보기 → 좋은 해 → 증상에서 도구로. “한 문장으로 보는 오늘”, 개념 카드, 출처 구역은 사용자 요청으로 제외 (2026-10-30).
- PDF: 1280px 화면 레이아웃을 세로 한 장으로 출력(버튼 숨김, 펼침 열기). A4 분할은 큰 상자가 밀려 빈 페이지가 생겨 쓰지 않음.

## 6. 동작과 접근성
목적별 보기 버튼(`aria-pressed`)으로 해당 칩 강조, 결과 개수를 `role="status"`로 안내. 코드 복사 성공·실패 안내. 인쇄 시 필터·버튼 숨김, `details` 모두 펼침, 코드 밝은 배경.

## 7. 검증 (2026-10-30)
Playwright + 시스템 Chrome으로 375·768·1280px 가로 넘침 없음(scrollWidth = 화면 폭), 내부 앵커 깨짐 없음, 필터·칩 이동·펼침 동작과 스크립트 오류 없음 확인. 헤드리스 Chrome `--window-size`는 최소 창 너비 때문에 375px 검증에 쓰지 않는다.
