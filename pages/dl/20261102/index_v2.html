문제

Q1이미지는 왜 MLP가 아니라 CNN으로 다룰까?

MLP는 이미지를 한 줄로 펴서 모든 픽셀을 모든 뉴런에 연결합니다. 이미지에는 세 가지 성질이 있는데, MLP는 이 셋 모두에서 손해를 봅니다 (UDL 10장 도입).

  • 차원이 크다 → 64×64×3 사진을 뉴런 128개에 연결하면 첫 층만 약 157만 개의 가중치가 필요합니다 (PDF p.18).
  • 가까운 픽셀끼리 관련이 있다 → 펴는 순간 “옆 픽셀”이라는 정보가 사라집니다. 픽셀 순서를 똑같이 섞어도 MLP는 똑같이 학습합니다.
  • 조금 옮겨도 같은 사진이다 → 몇 픽셀만 옮겨도 입력 전체가 바뀝니다. MLP는 같은 패턴을 위치마다 따로 배워야 합니다.

그래서 필요한 것: 가까운 것만 보고, 모든 위치에서 같은 방식으로

해결

복습

뉴런 = 가중합 + bias. 합성곱도 같은 계산입니다. 다른 점은 둘뿐입니다. ① 가까운 입력에만 연결되고 ② 모든 위치가 같은 가중치를 씁니다. 그래서 합성곱은 “가중치 대부분이 0이고 나머지는 같은 값인 MLP”라고 볼 수 있습니다 (UDL 10.2.4).

문제

Q2넓게 보려면 큰 창을 쓰면 될 텐데, 왜 kernel_size=3처럼 작은 창을 여러 번 쌓을까?

해결

쌓으면 넓어지고, 줄이면 더 빨리 넓어진다

수용영역receptive field

출력 한 칸이 원본에서 보는 범위. 3×3을 한 번 쌓을 때마다 2칸씩 넓어집니다: 3 → 5 → 7 … 층이 깊을수록 작은 패턴(선)이 모여 큰 패턴(눈, 얼굴)이 됩니다.

UDL 10.2.6 (그림 10.6)

그럼 왜 큰 창 하나가 아닌가

5×5 한 번25·C²비선형 1번
3×3 두 번18·C²같은 5칸을 보고 비선형 2번

같은 범위를 보면서 가중치는 약 28% 적고, 사이에 ReLU가 한 번 더 들어가 더 복잡한 패턴을 표현합니다 (C = 채널 수).

VGG 논문 (Simonyan & Zisserman, 2014) UDL 본문 밖 · UDL 10.5.1

왜 Max인가

최댓값은 영역 안에서 패턴이 조금 움직여도 대부분 그대로입니다. 그래서 작은 이동에 덜 민감해집니다(부분 불변). 1단계의 합성곱은 “옮기면 같이 옮겨짐”(등변)이고, Pooling은 “조금 옮겨도 같음”(불변)을 더합니다. 평균(Average)보다 Max가 나았다는 비교 실험도 있습니다.

UDL 10.1 · 10.4.1 · 10장 Notes (Scherer et al., 2010)

문제

Q4공간을 ½로 줄이면 정보가 줄어든다. 그래서 채널을 16 → 32로 늘리는데, 왜 하필 2배일까?

해결

“어디에”를 “무엇이”로 바꾸기

공간 칸 수는 ¼로 줄지만, 채널이 늘면 한 칸에 담는 패턴 종류가 많아집니다. 뒤로 갈수록 “어디에 있나”보다 “무엇이 있나”가 중요해지므로 이 교환이 맞습니다. UDL도 전형적인 CNN을 “공간은 ½씩, 채널은 2배씩”으로 정리합니다.

UDL 10.6 · 10.5.1 (VGG)

왜 정확히 2배인가 · 연산량 계산

Conv 한 층의 계산량 ∝ H × W × Cin × Cout × K²

H·W가 각각 ½ → ×¼, Cin·Cout이 각각 2배 → ×4. 곱하면 1, 층마다 계산량이 비슷하게 유지됩니다. 특정 층만 병목이 되지 않게 하려는 설계 규칙입니다.

ResNet 논문 (He et al., 2016) UDL 본문 밖

Q4 답줄어든 위치 정보를 패턴 종류로 바꿔 담고, 층마다 계산량을 고르게 하려는 규칙입니다. 다만 2배는 설계 관례이고, SmallCNN의 16·32는 실험으로 정하는 값입니다.

문제

Q12Head가 낸 점수 [N,K]는 얼마나 맞았나? 왜 손실은 CrossEntropyLoss이고, 모델 끝에 Softmax를 넣지 않을까?

해결

① 점수 = logit

Head의 출력은 아무 범위의 실수. 아직 확률이 아닙니다.

② Softmax → 확률

지수를 취해 모두 양수로 만들고, 합이 1이 되게 나눕니다. 클래스 K개의 확률 분포가 됩니다.

③ 손실 = −log(정답 확률)

정답 확률이 1에 가까우면 손실 ≈ 0, 낮을수록 손실이 커집니다.

이론

UDL의 손실 함수 만들기 공식: ① 출력에 맞는 확률 분포를 고르고(분류 → 범주 분포), ② 모델이 그 분포의 값을 예측하게 하고(Softmax), ③ 정답이 나올 확률을 최대화합니다(최대우도). ③을 음의 로그로 바꾸면 그대로 CrossEntropy가 됩니다. 즉 CrossEntropy는 임의로 고른 손실이 아니라 “정답 확률을 높여라”의 수식입니다 (UDL 5.2 · 5.5 · 5.7).

Q12 답분류에서 정답 확률을 최대화하는 것이 곧 CrossEntropy를 최소화하는 것이기 때문입니다. PyTorch의 CrossEntropyLoss는 Softmax를 안에 포함하므로 모델은 logit만 내보냅니다(PDF p.61). 예측 클래스는 logits.argmax(dim=1).

4단계 · 깊게 쌓아도 학습되게 — Residual과 BatchNorm

3·6교시 · 위치: 특징 추출부(Backbone) · UDL 11.1~11.5

문제

Q8층을 더 쌓으면 오히려 성능이 떨어진다. 그런데 train 성능도 같이 떨어진다. 왜일까?

train까지 나빠진다는 것은 과적합(일반화 문제)이 아니라 학습 자체가 안 되는 문제라는 뜻입니다. 깊은 망에서는 앞쪽 층의 파라미터를 조금만 바꿔도 기울기가 예측할 수 없게 바뀝니다. 손실 지형이 매끈한 언덕이 아니라 “작은 산이 무수히 많은” 모양이 되어 내려가기 어려워집니다 (UDL 11.1).

해결

Residual 연결residual · skip connection

출력 = x + f(x). 각 블록은 입력을 통째로 바꾸지 않고 바꿀 양만 배웁니다. 입력이 그대로 지나가는 길이 있어 정보와 기울기가 깊은 망을 통과합니다.

UDL 11.2

그런데 새 문제 → BatchNorm

x에 f(x)를 계속 더하면 값의 크기(분산)가 블록마다 커져, 깊어질수록 폭발합니다 (UDL 11.3).

BatchNorm: 채널마다 batch와 위치 전체의 평균·표준편차로 값을 정규화한 뒤, 배울 수 있는 배율 γ·이동 δ를 적용합니다.

UDL 11.3 · 11.4

Q8 답깊은 망은 손실 지형이 거칠어 학습이 막힙니다. Residual은 “입력 + 바꿀 양” 구조로 지름길을 만들어 이를 풉니다. 그 결과 1000층도 학습할 수 있게 되었습니다 (UDL 11.6).
Q9 답 · BatchNorm이 있으면 왜 잘 되나UDL은 세 가지를 듭니다. ① 값의 크기가 층마다 안정됩니다. ② 손실 지형이 매끄러워져 큰 학습률을 써도 됩니다. ③ batch마다 통계가 조금씩 달라 생기는 잡음이 약한 정규화가 됩니다. 평가 때는 batch 통계 대신 학습 중 저장해 둔 통계를 씁니다. 그래서 model.train()과 model.eval()의 동작이 다릅니다 (UDL 11.4.1).
4단계 결과

ResNet18 = 지금까지의 모든 것

7×7 Conv · MaxPool→ layer1 64ch→ layer2 128ch→ layer3 256ch→ layer4 512ch→ Global Avg Pool → fc

각 layer = Residual 블록 2개(Conv–BatchNorm–ReLU + 지름길). layer가 넘어갈 때마다 공간 ½ · 채널 2배(2단계 Q4), 끝은 Global Avg Pool + Linear 하나(3단계 Q6). 파라미터 약 1,170만 개. 참고: UDL 그림은 BN→ReLU→Conv 순서(v2), torchvision ResNet18은 Conv→BN→ReLU 순서(v1)입니다.

5단계 · 데이터가 적을 때 — 증강과 전이학습

4·6교시 · 위치: 모델 밖(데이터 준비·모델 선택) · UDL 9.3.6 · 9.3.8

문제

파라미터는 많고 데이터는 적다 → 과적합

복습

과적합 = train은 잘 맞히는데 새 데이터(valid)에는 약한 상태. UDL은 일반화를 높이는 방법을 네 갈래로 정리합니다: 함수를 부드럽게 · 데이터를 늘리기 · 모델 합치기 · 넓은 최소점 찾기. 오늘의 두 방법은 “데이터 늘리기”(증강)와 “좋은 출발점”(전이학습)입니다 (UDL 9.4, 그림 9.14).

문제

Q10RandomHorizontalFlip 같은 증강은 왜 효과가 있고, 왜 train에만 쓸까?

해결

증강 = 불변성을 데이터로 가르치기augmentation

라벨이 바뀌지 않는 변환(뒤집기·회전·색 변화)으로 같은 사진의 변형을 만들어, “이런 변화는 무시해라”를 가르칩니다.

1·2단계에서 합성곱과 Pooling은 이동에 대한 둔감함을 구조로 넣었습니다. 뒤집기·회전·밝기처럼 구조로 넣기 어려운 둔감함은 데이터로 넣습니다. 둘은 같은 목표의 두 방법입니다.

UDL 9.3.8 · 10.1

주의 · 라벨을 바꾸는 변환

오늘 실습 데이터는 가로 줄무늬와 세로 줄무늬입니다(PDF p.2). 90° 회전하면 가로가 세로가 되어 라벨이 바뀝니다. 좌우 뒤집기는 줄무늬 방향을 바꾸지 않으므로 안전합니다. 증강은 항상 “이 변환 후에도 같은 클래스인가?”를 먼저 묻습니다.

UDL 9.3.8 (“라벨이 유지되는 변환”)

Q10 답증강은 무시해야 할 변화를 데이터로 알려 줘서 데이터를 늘린 효과를 냅니다. valid/test는 모델을 고르고 확인하는 자라서, 할 때마다 결과가 달라지면 안 되므로 무작위 변환을 빼고 결정적 변환만 씁니다(PDF p.54).
문제

Q11남의 데이터(ImageNet)로 배운 ResNet18이 왜 우리 줄무늬 분류에 도움이 되고, 사전학습 층은 왜 lr=1e-4처럼 작게 학습할까?

해결

전이학습 = 좋은 출발점에서 시작transfer learning

데이터가 많은 관련 작업(ImageNet: 128만 장, 1,000 클래스)으로 먼저 학습한 뒤, 마지막 층(Head)을 떼고 새 층을 붙입니다. 본체(Backbone)는 고정하거나 미세조정합니다. UDL은 이를 “파라미터 대부분을 좋은 해가 있을 법한 곳에서 시작하게 하는 초기화”로 봅니다.

앞쪽 층은 색·질감·선처럼 어떤 사진에나 쓰이는 특징을, 뒤쪽 층은 물체 종류와 관련된 특징을 배웁니다. 그래서 앞쪽은 그대로 빌리고 뒤쪽부터 엽니다.

UDL 9.3.6 · 10.5.1 · 10장 Notes (Bau et al., 2017)

어디까지 고정하나 · 왜 작은 lr인가

앞쪽 층layer4Head Head-only고정고정1e-3 Partial고정1e-41e-3 전체 미세조정작은 lr작은 lr학습

사전학습 층은 이미 좋은 출발점에 있습니다. 큰 lr로 크게 움직이면 그 출발점을 벗어나 빌려 온 특징이 망가집니다. 새 Head는 무작위에서 시작하므로 큰 lr로 빨리 맞춥니다. 고정한 층의 BatchNorm은 4단계의 저장 통계를 유지하도록 eval()로 둡니다.

PDF p.75~77 · UDL 9.3.6 · 11.4

Q11 답사진의 기초 특징은 데이터가 달라도 공통이라 빌려 쓰면 적은 데이터로도 출발점이 좋습니다. 작은 lr은 그 출발점을 지키면서 조금만 맞추기 위해서입니다. 사전학습 때와 같은 입력 조건(weights.transforms()의 크기·Normalize)을 맞추는 것도 같은 이유입니다(PDF p.74).

코드로 보기 · 줄마다 몇 단계의 답인가

SmallCNN과 전이학습 코드의 각 줄에 그 줄이 답하는 단계와 질문을 붙였습니다.

# 5단계 · 데이터: 증강은 train에만 (Q10)
train_tf = transforms.Compose([transforms.Resize((64, 64)),
                               transforms.RandomHorizontalFlip(),   # 줄무늬 방향은 그대로
                               transforms.ToTensor()])
valid_tf = transforms.Compose([transforms.Resize((64, 64)), transforms.ToTensor()])

class SmallCNN(nn.Module):
    def __init__(self, num_classes):
        super().__init__()
        self.features = nn.Sequential(
            nn.Conv2d(3, 16, 3, padding=1),   # 1단계 합성곱(Q1) · 3×3(Q2) · padding(Q3)
            nn.ReLU(),                        # 2단계 비선형(Q7)
            nn.MaxPool2d(2),                  # 2단계 공간 ½(Q5)
            nn.Conv2d(16, 32, 3, padding=1),  # 2단계 채널 16 → 32(Q4)
            nn.ReLU(),
            nn.MaxPool2d(2),
        )
        self.pool = nn.AdaptiveAvgPool2d(1)   # 3단계 전체를 모으기(Q6)
        self.fc = nn.Linear(32, num_classes)  # 3단계 Head → logit

    def forward(self, x):
        x = self.features(x)
        x = torch.flatten(self.pool(x), 1)
        return self.fc(x)                     # Softmax 없음(Q12)

loss_fn = nn.CrossEntropyLoss()               # 3단계 정답 확률 최대화(Q12)

# 4·5단계 · 전이학습: ResNet18 = Residual + BatchNorm (Q8·Q9 · Q11)
weights = ResNet18_Weights.DEFAULT
model = resnet18(weights=weights)              # 좋은 출발점
for p in model.parameters():
    p.requires_grad = False                    # Backbone 고정
model.fc = nn.Linear(model.fc.in_features, num_classes)   # Head 교체
for p in model.layer4.parameters():
    p.requires_grad = True                     # Partial: 뒤쪽부터 연다
optimizer = torch.optim.AdamW([
    {"params": model.layer4.parameters(), "lr": 1e-4},   # 출발점을 지키는 작은 lr
    {"params": model.fc.parameters(), "lr": 1e-3},       # 새 Head는 빠르게
])
# 입력 전처리는 weights.transforms()로 사전학습 조건에 맞춘다(Q11)
