## 4일 요약

> Day5에서 무엇을 예측할지와 입력으로 쓸 열을 정하고, 데이터를 train·valid·test로 나눠 전처리 Pipeline을 만들었습니다. Day6~7은 같은 데이터·분할·전처리를 그대로 두고 모델만 바꿔 비교했습니다(선형회귀·로지스틱회귀·KNN → Decision Tree·Random Forest·XGBoost). Day8에서 지표와 임계값을 정한 뒤 보관해 둔 test로 한 번 최종 평가했습니다. 날이 갈수록 모델은 복잡해지고, 평가는 valid 한 번 → train 안 5-fold 교차검증 → test 최종 평가로 엄격해집니다.

4일 공통 데이터: AI 업무 요청 합성 데이터 100건. 입력 4열(`input_chars`, `allowed_tools`, `task_type`, `priority`), 정답은 분류 `failed`(실패 1) · 회귀 `elapsed_ms`.

매일 수업 순서: 개념·시연 → 실습 → 7교시 프로젝트 통합 → 8교시 재실행·설명

## 2. 날짜별 비교

열은 위와 같은 날짜입니다. 그날 새로 추가된 부분은 날짜 색으로 표시합니다.

### 2-1. 내부 구조 (입력에서 결과까지의 처리 순서)

| Day5 | Day6 | Day7 | Day8 |
|---|---|---|---|
| 요청 데이터 → **X·y 분리** → **60·20·20 분할** → **ColumnTransformer**(수치: 대체·표준화 / 범주: 대체·One-hot) → 8열 → **DummyClassifier** | 같은 Pipeline → 모델 자리: **LinearRegression**(가중합) · **LogisticRegression**(가중합 → 확률 → 0.5 기준 클래스) · **KNN**(거리 → 이웃 K개 투표·평균) | 같은 Pipeline → **Decision Tree**(조건 분기 → 잎의 다수결·평균) · **Random Forest**(트리 여러 개 → 투표·평균) · **XGBoost**(트리를 차례로 더해 오차 보정) → **5-fold CV** | **파생 특성** → Pipeline → 확률 점수 → **임계값** → 클래스 · **선택 계획 기록 → 개발 80건 재학습 → test 20건 평가** · **K-Means**(정답 없이 할당·중심 갱신) |
| 모델 없음. 전처리 틀을 만든다 | 학습하는 모델이 처음 등장 | 모델 여러 개를 결합 | 모델은 그대로, 평가 절차가 추가 |

### 2-2. 메소드 (단계별 대표 메소드, 모두 scikit-learn · Day7은 XGBoost 포함)

4일 공통: `fit`(train에서 학습) · `transform` / `predict`(valid·새 입력에 적용)

| 단계 | Day5 | Day6 | Day7 | Day8 |
|---|---|---|---|---|
| 준비 | `train_test_split` · `SimpleImputer` · `OneHotEncoder` · `StandardScaler` | `MinMaxScaler` · `clone` | `StratifiedKFold` | `FunctionTransformer` (파생 특성) |
| 처리·모델 | `ColumnTransformer` · `Pipeline` · `DummyClassifier` | `LinearRegression` · `LogisticRegression` · `KNeighborsClassifier`·`Regressor` | `DecisionTreeClassifier` · `RandomForestClassifier` · `XGBClassifier` | `KMeans` · `cross_validate` |
| 결과 확인 | `get_feature_names_out` · `joblib.dump` | `coef_` · `predict_proba` · `kneighbors` · `root_mean_squared_error` · `f1_score` · `confusion_matrix` | `cross_val_score` · `feature_importances_` · `permutation_importance` | `precision_score` · `recall_score` · `roc_curve` · `roc_auc_score` · `silhouette_score` |

요약 한 줄: 사용법(`fit`·`predict`)은 4일 내내 같고 모델 클래스만 바뀐다. 결과를 확인하는 함수는 날마다 늘어난다.

### 2-3. 주요 파라미터 (날짜별로 사람이 정하는 주요 값)

| Day5 · 분할·전처리 정책 | Day6 · 모델 설정 | Day7 · 모델 복잡도·검증 방식 | Day8 · 판단 기준 |
|---|---|---|---|
| `test_size`: 떼어 낼 비율. 분모에 주의 (전체 100의 0.2 → 남은 80의 0.25) | `C`: LogisticRegression 규제 강도의 역수 (작을수록 규제가 강함) | `max_depth`: 트리가 질문을 이어 갈 최대 깊이 | 임계값(threshold): 실패 확률을 클래스로 바꾸는 기준 (기본 0.5) |
| `stratify`: 각 분할의 실패 비율을 같게 유지 | `n_neighbors`: KNN이 참고할 이웃 수 K | `n_estimators`: Random Forest·XGBoost에서 만들 트리 수 | `scoring`: CV에서 비교할 지표 (`f1`, `roc_auc`, `neg_root_mean_squared_error`) |
| `strategy`: 결측을 채울 값 (`median`, `most_frequent`) | `weights`: 이웃 투표 방식 (`uniform` 같은 비중 / `distance` 가까울수록 크게) | `learning_rate`: XGBoost에서 트리 하나의 보정을 얼마나 반영할지 | 양성 라벨(`labels=[0, 1]`): 실패 1을 양성으로 고정. Precision·Recall의 분모가 정해짐 |
| `handle_unknown`: train에 없던 범주가 들어올 때 처리 (`ignore`면 모두 0) | Scaler 종류: 거리의 기준을 바꿈 (`StandardScaler` / `MinMaxScaler`) | `n_splits`: 교차검증 fold 수 (5) | `n_clusters`: K-Means 군집 수 |

실측(값을 바꿨을 때 결과 변화)은 넣지 않습니다.

### 2-4. 평가 기준 (결과를 무엇과 비교해 평가하나)

| Day5 | Day6 | Day7 | Day8 |
|---|---|---|---|
| 전처리 결과의 형식과 기준선 확인: train `(60, 8)`·valid `(20, 8)`, 금지 열 없음, Dummy Accuracy와 실패 발견 수를 따로 계산 | 같은 valid에서 기준선과 비교: 회귀 MAE·RMSE·R², 분류 F1·혼동행렬 | 과적합과 점수 흔들림 확인: train·valid 점수 차이, 5-fold 평균·표준편차, 중요도는 인과관계가 아님 | 업무 기준으로 최종 확인: Precision·Recall의 분모, ROC-AUC와 임계값은 따로 해석, CV로 선택 → test는 한 번만 |

요약 한 줄: 모델이 복잡해질수록 valid 점수 하나 대신 여러 번 나눠 본 점수를 보고, 최종 test 점수는 선택이 끝난 뒤에 한 번 본다.
