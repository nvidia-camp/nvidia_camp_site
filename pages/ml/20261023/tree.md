### 1교시 · 문제 정의와 입력·정답 구분

#### 학습 방식과 예측 목적

##### 머신러닝은 무엇을 배우는가? (PDF p.9)

- 규칙 기반은 사람이 조건을 작성하고 지도학습은 과거 X·y의 관계 학습.
- 명확한 규칙 문제는 단순 코드가 적절할 수 있으며 학습 목표는 새로운 입력의 유효 예측.

##### 문제 유형은 무엇을 얻고 싶은지로 정한다 (PDF p.10)

- 범주 정답은 분류, 수치 크기·오차는 회귀, 정답 없는 구조 탐색은 비지도학습.
- 보상에 의한 정책 학습과 생성 목적의 구분은 서로 다른 분류 축.

##### 0과 1이면 회귀일까, 분류일까? (PDF p.11)

- 0·1의 자료형보다 성공·실패라는 범주 의미로 문제 유형 판단.
- 시간 크기·군집 번호·수량 예측 등 출력의 목적 구분.

##### 학습과 추론은 입력이 다르다 (PDF p.12)

- 학습에는 과거 실행 전 X와 실행 후 y를 함께 사용.
- 추론은 정답이 아직 없는 X에 저장된 전처리·모델 규칙 적용.
- 과거 정답 보유와 예측 불가능 시점의 정보를 입력에 넣는 누수 구분.

#### 공통 사례와 데이터 계약

##### 공통 사례 · 실행 전에 요청 실패를 예상한다 (PDF p.13)

- 한 행은 독립 요청, 예측은 접수·설정 후 실행 직전.
- 정답은 종료 상태의 실패 여부이며 합성 100건에 성공 70·실패 30.
- 전날 EDA 13행과 별도 제작한 학습 자료 구분.

##### 같은 표에 있어도 역할은 다르다 (PDF p.14)

- 실행 전 글자 수·허용 도구 수·작업 유형·우선순위를 X로 사용.

- request_id는 분할 추적용이며 allowed_tools는 실제 호출 횟수가 아닌 설정.

##### 합성 데이터 100행 중 처음 5행 (PDF p.15)

- 100행 중 일부 예시로 수치형 결측과 입력·정답 구조 확인.
- 결측과 실제 0 구분, 예제의 정답 결측·ID 중복 없음 확인.

##### 입력 X와 정답 y를 분리한다 (PDF p.16)

- 입력 열 허용 목록으로 X 4열과 y 1개를 복사해 분리.

##### 분할 전에 평균을 구하면 무엇이 바뀔까? (PDF p.22)

##### 출력으로 누수를 설명한다 (PDF p.23)

- valid 관측값이 train 결측 대체값에 영향을 주는 통계 누수 구조.
- 정답을 쓰지 않아도 데이터에서 대표값을 배우는 작업은 fit에 해당.
- valid 변환은 저장된 train 평균을 바꾸지 않음.

##### 모든 정제를 분할 뒤로 미뤄야 할까? (PDF p.24)

- 사전 고정한 행별 공백·형식 규칙과 데이터에서 배우는 통계를 구분.

### 3교시 · 데이터 분할과 무결성

#### 분할의 역할과 두 단계 실행

##### Train·Validation·Test의 역할 (PDF p.28)

- train은 학습, valid는 후보 비교, test는 설정 확정 후 일반화 확인.
- valid·test의 정답은 존재할 수 있으나 사용하는 목적과 시점이 다름.

##### 100행을 60 : 20 : 20으로 나누는 예 (PDF p.29)

- 전체의 20%를 test로 보관한 뒤 나머지 80행의 25%를 valid로 분리.
- 60·20·20은 당일 예시이며 시간·그룹·목표에 따라 설계 변경 가능.

##### 1차 분할 · test 20행을 보관한다 (PDF p.30)

- X와 y를 같은 호출에서 나누고 클래스 비율을 고려한 test 20행 확보.
- seed와 분할 후 크기·클래스 수 확인.

##### 2차 분할 · 개발용에서 valid를 만든다 (PDF p.31)

- 개발용 X·y에서 25% valid를 떼어 train 60·valid 20 생성.
- 두 번째 호출에 test는 넣지 않고 현재 나누는 y_dev로 층화.

#### 설정 한계와 무결성 검사

##### stratify와 random_state가 보장하지 않는 것 (PDF p.32)

- stratify는 클래스 비율, random_state는 동일 조건의 재현을 보조.
- 그룹 독립·시간 적합성·좋은 성능·공정성은 별도 검토.
- 희귀 클래스 오류를 층화 제거로만 해결하지 않고 표본·목적 확인.

##### 분할의 교집합과 X/y 정렬을 검사한다 (PDF p.33)

- 분할 ID의 교집합 0과 합집합 전체 100개 확인.
- X와 y의 ID뿐 아니라 행 순서까지 같은지 검사.

##### 무작위·그룹·시간 중 무엇으로 나눌까? (PDF p.34)

- 독립 요청은 무작위, 새 고객·문서는 그룹, 미래 요청은 시간 순서로 설계.

##### 실습 03 · 60·20·20 분할과 무결성 검사 (PDF p.36)

- 처리기 이름·객체·열 목록으로 열별 경로 구성.
- remainder=drop으로 미지정 열 제외 후 train (60,8)·valid (20,8) 및 유한값 검사.

##### 변환된 열 이름과 행 ID를 보존한다 (PDF p.59)

- 학습 후 출력 특성명을 받아 변환 배열에 열 이름 복원.
- 입력 요청 ID와 행 순서를 다시 붙여 정답·예측의 대응 유지.

##### 8개 출력 열은 어디에서 왔는가? (PDF p.60)

- 8열은 수치 특성 2개·작업 유형 One-hot 3개·우선순위 One-hot 3개.
- failed·status·elapsed_ms·retry_count·request_id가 출력 특성에 들어가지 않는지 감사.

#### Dummy 기준선과 결과 해석

##### 기준선 · 아무 패턴도 쓰지 않으면 몇 점일까? (PDF p.61)

- DummyClassifier는 train 최다 클래스만 기억하는 비교 출발점.
- 입력 특성의 관계를 배우지 않으므로 향후 예측 모델로 교체할 기준선.

##### 전처리와 기준선을 하나의 Pipeline으로 (PDF p.62)

- 열별 전처리와 Dummy를 하나의 Pipeline으로 연결해 train fit·valid predict.
- 예측 20개와 모두 성공 클래스인 결과 구조 확인.

##### 0.70이라는 점수만 보고 좋아하면 안 된다 (PDF p.63)

- 전체 정확도와 실제 실패 탐지 수를 별도 계산.
- 자료의 Accuracy 0.70에도 실패 발견은 0/6인 기준선 한계.

##### 같은 결과를 성공·실패로 나누어 읽는다 (PDF p.64)

- 실제 성공·실패와 예측 성공·실패의 개수로 같은 결과 재해석.
- 70% 정확과 실패를 찾아낸다는 주장은 서로 다른 의미.

#### 새 요청과 통합 실습

##### 새 요청 · 정답 없이도 변환과 예측한다 (PDF p.65)

- 정답 없는 새 입력의 수치 결측·미지 범주에 학습된 규칙 적용.
- 2건 입력을 8열로 변환하고 y 없이 예측.
- Dummy의 성공 예측을 실제 성공 보장으로 해석 금지.

##### 실습 06 · 열별 전처리와 기준선 연결 (PDF p.66)

- 기본필수는 두 경로의 8열 구성·유한값 검사.
- 응용은 기준선 0.70·실패 0/6 해석과 새 요청 2건, 심화는 특성명·금지 열·입력 계약 검사.
- 완료는 8열 설명·train-only fit·valid와 새 입력 증거.

**핵심:** 열별 처리와 단계 순서를 결합하고 기준선의 전체 정확도와 실패 탐지 한계를 구분.

### 7교시 · 검증·저장·프로젝트 통합

#### 누수 감사와 입력 검사

##### Pipeline만 썼다고 누수 검사가 끝나지 않는다 (PDF p.67)

##### valid 값이 바뀌어도 학습 통계는 그대로 (PDF p.68)

- valid 복사본 값을 크게 바꿔 transform해도 중앙값 통계가 같은지 확인.
- 저장 대표값이 train 중앙값과 일치하는지 직접 대조.
- 진단 입력과 원본 valid·test 구분.

##### 새 범주와 누락된 열은 다른 오류다 (PDF p.69)

- 새 범주는 필요한 열이 존재하지만 값이 새로움, 누락 열은 입력 구조 자체의 결손.
- 필수 열 목록을 예측 전에 검사하고 One-hot ignore로 누락 열을 해결하지 않음.

##### 검증 결과를 읽는 순서 (PDF p.70)

- 행 ID·개수→전처리 구조와 통계→기준선 결과→합성·소표본 한계 순서로 검증.
- Dummy는 X 관계를 쓰지 않으므로 그 점수로 전처리 우열을 선택하지 않음.
