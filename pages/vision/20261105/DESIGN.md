# Day14 oneday 요약 디자인

## 1. 기준과 목적

- **목적:** 수강생이 **한 장만 보고** 오늘 하루 무엇을 배우고, 어떤 파라미터를 이해해야 하는지 파악하게 한다. 실습 프로젝트 안내가 아니라 개념 이해가 중심이다.
- **위치:** 이 형식은 Day13까지 쓰던 `DayN_개념지도/`를 대신한다(사용자 결정, 2026-11-05).
- **구성안:** `nvidia_camp/04_vision/20261105/Day14_개념가이드_00_하루개요.md` (강의 자료 쪽 문서를 `build.py`가 읽는다).
  - 내용과 순서는 이 문서를 따른다.
  - `build.py`가 이 문서에서 다음을 직접 읽는다. 원고와 결과물이 어긋나지 않게 하기 위해서다.
    - 핵심 코드
    - "응용·심화는 무엇을 더 요구하나" 표
    - 파라미터 지도 A~F
- **범위:** 강의 PDF `Day14_20261105.pdf`(99쪽), 실습 코드(기본필수·응용·심화).
  - 특심화는 제외한다.
  - 교재 연결은 넣지 않고, 하단에 출처만 둔다(사용자 지정).
- **디자인 기준:** `sesac-html-design` 스킬, Day13 개념 지도의 디자인 결(구역 틀·카드·배지·색 띠).

## 2. 사용자 지정

- 제목은 주제명 "전이학습 기반 이미지 분류"로 한다.
- 배치는 구성안 흐름 그대로 둔다.
- "손잡이" 같은 비유 대신 "파라미터"라는 말을 그대로 쓴다.
- "수강생용" 배지는 붙이지 않는다.
- 파라미터 지도에 중요도(★)를 표시하지 않는다. 항목은 모두 넣되 표 형태가 아니게 한다.
- 헷갈리는 개념일수록 그림을 넣는다.
- 방향은 내용에 맞춘다. 이번 결과물은 세로 한 장이고, 흐름은 칸 안에서 가로로 둔다.
- 용어는 원어나 제대로 번역된 말을 쓴다.
  - Accuracy (`accuracy_score`와 같은 지표라서 '정확도' 대신 씀)
  - Confusion matrix
  - Occlusion 실험·Occlusion 영역 ('가림'이라고 쓰지 않음)
  - Backbone은 '모양을 보는 눈' 같은 비유 대신 **특징 추출기**, Head는 **분류기**로 쓴다. 강의 PDF p.5의 "Backbone은 특징을 만들고, Head는 클래스 점수로 바꿉니다"를 따른 것이다.

## 4. 레이아웃 (구성안 순서)

1. **머리말:** 배지(새싹 학습 노트 · Day14 날짜·과목 · oneday 요약) + 제목 + "오늘 한 문장".
2. **한 장으로 보는 전이학습:** 실제 도형 사진 → Backbone(빌려 옴) → 특징 256 → Head(새로 학습) → 점수 3개 → 예측. 아래에 하루 약속 3개를 둔다.
3. **하루 전체 지도:** 준비 / 학습과 평가 / 설명과 정리를 강의 PDF p.3 색으로 칠한 세 구역에 둔다.
   - 교시 카드에는 핵심 질문과 개념 칩을 넣는다.
   - 끝에는 "다음 실험 가설 → 1교시"를 둔다.
4. **교시별 핵심:** 교시마다 한 줄 계단(기본 → 응용 → 심화)을 그린다.
5. **코드로 보는 하루 흐름:** 아래 네 부분으로 나눈다.
   - ①~⑦ 흐름 띠.
   - 핵심 코드: 교시 블록마다 왼쪽에 구역 색 띠를 두고, 오른쪽에 설명 칸을 둔다.
   - 코드 속 파라미터 13행. 행마다 **위 코드**(핵심 코드 그대로) → **고친 코드**(바뀐 부분 노란 표시) → **결과**(전 → 후, 조건·데이터)를 읽는다.
     - 변경 종류별로 4묶음: 숫자·옵션만 바꾸기 / 코드 한 줄 넣기·빼기 / 순서만 바꾸기 / 모델은 그대로, 고르고 읽는 방법만 바꾸기.
     - 실험이 아닌 항목(폴더 이름, Head 크기, CAM 대상 층, confusion matrix `labels`)은 파라미터 지도에만 둔다.
     - **꼭 기억** 7행에는 배울 점을 붙였다. 예전 6구역 '실측 7가지'가 이 파트와 중복이라 합쳤다(사용자 결정, 2026-11-05).
     - 이전 판들: "원래/바꾸면" 카드는 무엇을 어떻게 고쳤는지 직관적이지 않았고, 5가지 다른 종류의 변경이 한 이름 아래 섞여 있었다.
   - "응용·심화는 무엇을 더 요구하나": 세 난이도 카드와 교시별 두 칸(응용 / 심화). 칸마다 이유를 둔다.
6. **전체 파라미터 지도:** A~F 여섯 묶음을 2열로 놓는다. 묶음마다 [그림] + [파라미터 줄(이름 · 오늘의 값 · 한 줄 의미)]을 둔다.
7. **출처:** 강의 PDF, 실습 코드, 실측 환경, 사전학습 모델 안내.

- **좁은 화면:** 75rem 이하에서 흐름을 세로로 쌓는다. 40rem 이하에서는 모든 카드를 1열로 둔다.

## 5. 그림 데이터

`make_figures.py`가 실습 데이터로 실제 학습을 돌려 `facts.json`을 만든다. 숫자와 PNG가 들어 있다. 설정은 seed 14, CPU 1-thread, 전체 데이터를 한 번에 넣는 방식이다.

| 묶음 | 그림 | 데이터 | 값 |
|---|---|---|---|
| A | 클래스별 샘플 3장, 개수 막대 | 응용 | train 120·40·20, valid 30·30·30 |
| A | 그룹 분할 도식 | 개념 그림 | — |
| B | 전략별로 열리는 층과 학습 파라미터 | 기본 | 771 / 1,923 / 2,187 (Conv1 216 · BN1 16 · Conv2 1,152 · BN2 32 · Head 771) |
| B | 두 스위치(`requires_grad`, `eval()`) | 개념 그림 + 기존 실측 | Partial BN train 모드: F1 0.956 → 0.790 |
| C | lr별 valid loss 곡선 | 응용, Head-only, 16 epoch | lr 0.1: 1·2 epoch 11.7·6.7, best 9 epoch, 마지막 16 epoch에서 다시 상승 |
| D | class weight 전후 recall | 응용 | [1.0, 0.933, 0.5] → [1, 1, 1], F1 0.804 → 1.0, weight [0.3, 0.9, 1.8] |
| D | class weight와 Sampler 비교 | 개념 그림 | — |
| E | 전부 circle로 예측한 예제 | 손 예제 (4·2·1) | Accuracy 0.571, Weighted 0.416, Macro 0.242 |
| E | Confusion matrix | 응용, weight 적용 전 | triangle 30장 중 15장을 circle로 예측 |
| F | 같은 이미지, target만 바꾼 Grad-CAM | 응용, weight 모델 | square 점수 +2.17(확률 0.949), circle 점수 −1.18(확률 0.033). circle은 음의 영역 72% |

- 코드 속 파라미터 행의 숫자는 구성안의 실측값이다. 이 실측은 강사용 코드를 임시 폴더에 복사해 실행해서 얻었다.
- 재확인(2026-11-05, `verify` 재실행) 결과는 다음과 같다.
  - Normalize 결과(Accuracy 1.0 → 0.933, 평균 확신도 0.90 → 0.955)는 **응용 데이터** 값이다. 기본 데이터에서는 1.0 그대로다. 그래서 출처 표시를 응용으로 고쳤다.
  - seed 비교(Macro F1 0.51~0.80)는 seed 5개(0·1·14·42·7) 결과다.
  - 1 epoch seed 비교(Accuracy 0.33~0.56)는 기본 데이터, seed 4개(0·1·14·42) 결과다.
- `.relu()` 카드의 "약 43%"는 구성안 작성 때 다른 이미지에서 잰 값이다. F 그림의 72%는 다른 target에서 잰 값이라 서로 다르다.

## 6. 검증 (2026-11-05)

- **화면:** Playwright와 시스템 Chrome으로 375·768·1280·1440px에서 확인했다.
  - 가로 넘침은 0px이다.
  - 스크립트 오류가 없다.
  - 스크린샷으로 글자 겹침과 줄바꿈을 직접 확인했다.
- **PDF:** `Day14_oneday요약.pdf`. 1440px 폭의 세로 한 장(1080 × 약 5,650pt)이다.
  - `pdftotext`로 글자를 추출할 수 있다.
- **코드:** 구성안의 핵심 코드는 문법 검사(`ast.parse`)를 통과했다.
  - 이 코드는 설명용으로 단순화한 이름(`load_pretrained_backbone`, `conv_layers`)을 쓰기 때문에 그대로 실행되지는 않는다. 화면에도 그렇게 적었다.

## 7. 다시 만들기

```bash
cd site/pages/vision/20261105
uv run --project ~/envs/dl python make_figures.py <실습 폴더(01_basic·02_intermediate 포함)> .   # facts.json
python3 build.py        # 구성안 + facts.json + template.html → index.html
uv run render.py        # index.html → Day14_oneday요약.pdf
```

## 8. 파일

- `index.html`: 웹용 문서. 그림이 안에 들어 있어서 파일 하나로 열린다.
- `Day14_oneday요약.pdf`: 배포용 세로 한 장 PDF
- `template.html`: 고정 문구와 스타일
- `build.py`: 구성안과 그림 데이터를 채워 넣는 스크립트
- `make_figures.py`: 실측 그림 데이터 생성
- `facts.json`: 그림 데이터
- `render.py`: PDF와 화면 검증 스크린샷 생성
- `DESIGN.md`: 이 문서
