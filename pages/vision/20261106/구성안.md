## 오늘을 한 문장으로

> **YOLO는 이미지를 한 번 보고 격자 칸마다 박스 후보를 낸다. conf와 NMS로 후보를 걸러 "무엇이(Class) 어디에(Box) 얼마나 확실하게(Confidence)" 있는지 남기고, 정답과의 IoU로 채점하고, 영상에서는 같은 객체를 Track ID로 잇는다.**

```text
이미지 ─▶ [ Backbone·Neck·Head ] ─▶ 후보 420개 ─conf─▶ 11개 ─NMS─▶ 4개 ─▶ Results
          격자 20×16 · 10×8 · 5×4      칸마다 박스 4개   점수 낮은       겹친 중복         │
          (촘촘 = 작은 객체,            + 클래스 점수 3개  후보 버림       지움              │
           성김 = 큰 객체)                                                                 ▼
                                                       정답 박스와 비교: 평가 IoU ≥ 0.5 → TP·FP·FN
                                                       (이 예: 정답 3개 → TP 3, NMS 기본값 0.7에서 남은 중복 1개는 FP)
```

실측: 응용 val 이미지 1장(standard_val_000, 정답 3개), 입력 160×128.

**꼭 알고 갈 YOLO 개념 세 가지** (이 그림 하나로 설명하고, 다른 구역은 이 그림을 가리킨다)
1. **격자 칸마다 후보를 하나씩 낸다.** 이미지를 한 번 보고(One-stage), 칸마다 "박스 숫자 4개 + 클래스별 점수"를 낸다. 객체가 3개여도 후보는 420개다.
2. **격자는 세 가지 크기다.** 촘촘한 격자는 작은 객체, 성긴 격자는 큰 객체를 맡는다. Neck이 여러 크기의 특징을 섞는 이유다.
3. **그래서 두 번 거른다.** conf는 점수 낮은 후보를, NMS는 같은 객체에 겹친 중복을 지운다. 정답과 비교하는 평가 IoU는 이 깔때기 밖, 채점할 때만 쓴다.

**하루 내내 지키는 약속 세 가지**
1. **train**으로 배우고, conf·checkpoint는 **val**로만 고르고, **test**는 마지막 확인용으로 남긴다
2. 비교할 때는 **한 번에 하나만** 바꾸고, 입력·가중치·imgsz·장치·버전을 함께 기록한다
3. **세 가지 기준을 섞지 않는다**: conf는 후보 점수, NMS IoU는 예측끼리의 겹침, 평가 IoU는 예측과 정답의 겹침

## 코드로 보는 하루 흐름

오늘 배우는 과정을 **공식 문서의 기본 사용법 그대로** 줄인 뼈대입니다. 위에서 아래로 읽으면 1교시부터 7교시까지 이어집니다. 8교시는 새로 쓰는 코드 없이 같은 명령을 다시 실행해 결과를 대조합니다. `image`, `pred_boxes`, `gt_boxes`는 이미 준비된 이미지 배열과 박스 텐서입니다.

### 흐름 요약

| 순서 | 하는 일 | 코드에서 일어나는 일 | 교시 |
|---|---|---|---|
| ① | 좌표 | 픽셀 xyxy → `box_convert`로 중심·크기 → 이미지 크기로 나눔 | 1 |
| ② | 채점 기준 | `box_iou`로 예측 × 정답 겹침 표 → 0.5 이상이면 같은 객체 | 2 |
| ③ | 라벨·데이터 | 라벨 한 줄 = `class cx cy w h`, dataset.yaml로 경로·클래스 연결 | 3 |
| ④ | 학습 | 구조(.yaml)로 모델 만들기 → `train()` → best.pt·last.pt | 4 |
| ⑤ | 검증 | `val()` → mAP50·mAP50-95 | 5 |
| ⑥ | 추론 | `predict(conf)` → 안에서 후보 420개 → conf → NMS → Results | 6 |
| ⑦ | 추적 | `track(tracker)` → Track ID | 7 |
| ⑧ | 재실행 | 같은 입력·설정으로 다시 실행해 이미지 수·프레임 수·지표 대조 | 8 |

### 핵심 코드

```python
import cv2
import torch
from torchvision.ops import box_convert, box_iou
from ultralytics import YOLO

# ── [1교시] 좌표: 픽셀 xyxy → YOLO 라벨(정규화 중심·크기) ──────────────
boxes = torch.tensor([[12, 18, 52, 58]], dtype=torch.float32)  # x1, y1, x2, y2
cxcywh = box_convert(boxes, in_fmt="xyxy", out_fmt="cxcywh")
labels = cxcywh / torch.tensor([160, 128, 160, 128])           # x는 W, y는 H로
cv2.rectangle(image, (12, 18), (52, 58), (0, 255, 0), 2)      # 색은 BGR

# ── [2교시] IoU: 예측과 정답이 얼마나 겹치나 ─────────────────────────
iou = box_iou(pred_boxes, gt_boxes)        # [예측 수, 정답 수] 겹침 표
matched = iou >= 0.5                       # 같은 클래스와 1:1로 연결되면 TP

# ── [3교시] 데이터: 라벨 TXT 한 줄 = 객체 하나 ───────────────────────
# labels/train/img_000.txt  →  0 0.200000 0.296875 0.250000 0.312500
#                              class cx cy w h  (객체 없는 이미지는 빈 파일)
# dataset.yaml  →  path · train · val · names  (아래 YAML)

# ── [4교시] 학습: 구조(.yaml)에서 시작해 데이터와 연결 ────────────────
model = YOLO("yolo26n.yaml")
model.train(data="dataset.yaml", epochs=60, imgsz=160)

# ── [5교시] 검증: 학습 뒤 model은 best.pt, val에서 채점 ──────────────
metrics = model.val()
metrics.box.map50, metrics.box.map         # mAP50, mAP50-95

# ── [6교시] 추론: 안에서 후보 420개 → conf → NMS → Results ────────────
results = model.predict("images/val", conf=0.25)
for result in results:
    result.boxes.xyxy, result.boxes.cls, result.boxes.conf  # 0개일 수도 있음

# ── [7교시] 추적: 프레임 사이 같은 객체에 ID를 잇는다 ─────────────────
results = model.track("demo.avi", tracker="bytetrack.yaml", stream=True)
for result in results:
    if result.boxes and result.boxes.is_track:
        track_ids = result.boxes.id.int().cpu().tolist()
```

3교시의 dataset.yaml:

```yaml
path: data              # 데이터 폴더
train: images/train     # path 기준 상대 경로
val: images/val
names:
  0: square
  1: circle
  2: triangle
```

### 코드 속 파라미터 — 어디를 고치면 무엇이 달라지나

위 핵심 코드 그대로(위 코드)에서 **한 부분만 고친 코드**로 다시 실행한 결과입니다(8개). 위 코드와 실행 조건이 다르면 조건 열에 적었습니다. **꼭 기억** 7개에는 배울 점을 붙였습니다. conf·NMS IoU 행은 1구역 깔때기의 어느 단계를 바꾼 것인지도 함께 적었습니다.

**숫자·옵션만 바꾸기** — 줄은 그대로 두고 값만 고쳤습니다

| 교시 | 파라미터 | 위 코드 | 고친 코드 | 결과 | 조건·데이터 | 꼭 기억 |
|---|---|---|---|---|---|---|
| 6 | conf | `model.predict("images/val", conf=0.25)` | `model.predict("images/val", conf=0.5)` | Precision 0.70 → **0.86** (박스 43 → 35), Recall 1.0 그대로. 0.9까지 올리면 Recall **0.4**(30개 중 18개 놓침) | 응용 val 12장 · 평가 IoU 0.5 | 깔때기의 첫 거름망. 올리면 거짓 탐지는 줄고 놓침은 늘어난다. P·R을 함께 본다 |
| 6 | NMS IoU | `model.predict("images/val", conf=0.25)` | `model.predict("images/val", conf=0.25, iou=0.5)  # 기본 0.7` | 박스 43 → **30**, FP 13 → **0**, Precision 0.70 → 1.0. conf 0.25에서 남은 FP 13개가 전부 같은 객체의 중복이었음. 0.95로 올리면 박스 105개 | 응용 val 12장 | 깔때기의 두 번째 거름망. 정답과 비교하는 평가 IoU와 이름만 같고 하는 일이 다르다 |

| 4 | epochs | `model.train(..., epochs=60, ...)` | `model.train(..., epochs=1, ...)` | mAP50 0.977 → **0**. 60 epoch 학습에서도 17 epoch까지는 0이었음 | 응용 데이터 · 처음부터 학습 | 1 epoch이 돌아간 것은 "연결 성공"이지 "탐지 성공"이 아니다 |
| 7 | persist | `model.track("demo.avi", ...)` | `model.track("demo2.avi", ..., persist=True)  # 다음 영상` | 새 영상인데 ID가 1부터 다시 시작하지 않고 앞 영상의 ID(1·3·6·24·26)를 이어 쓰며 45까지 커짐. 새 YOLO 객체로 시작하면 첫 실행과 같은 ID | 같은 모델 객체로 demo 영상을 다음 영상처럼 한 번 더 | Track ID는 모델에 저장된 값이 아니라 실행 중 상태다. persist는 같은 영상 안에서만 쓴다 |

### 응용·심화는 무엇을 더 요구하나

세 난이도는 같은 코드 흐름을 쓰지만, **요구하는 수준**이 다릅니다.

| | 기본필수 | 응용 | 심화 |
|---|---|---|---|
| 핵심 질문 | 어떻게 동작하나? | 무엇을 바꾸면 결과가 달라지나? | 그 결론을 믿어도 되나? |
| 요구하는 것 | 흐름을 끝까지 돌리고, 각 출력의 의미를 안다 | 값 하나를 바꿔 결과 차이를 **재고 설명**한다 | 그 차이가 **누수·설정·우연 탓이 아님**을 보인다 |
| 결과를 보는 눈 | 박스가 나오나 | 숫자가 **얼마나** 달라지나 | 다른 조건·새 프로세스에서도 **같은 결론**인가 |

| 교시 | 응용이 더 요구하는 것 | 심화가 더 요구하는 것 |
|---|---|---|
| 1 좌표 | **왕복 변환** 오차 확인. 저장한 숫자를 다시 그려야 틀린 정규화가 드러남 | 경계 **clip**과 작은 박스. 이미지 밖 좌표는 면적이 달라져 IoU가 바뀜 |
| 2 지표 | conf와 **NMS IoU**를 따로 바꿔 비교. 두 값은 깔때기의 서로 다른 단계를 바꿈 | **클래스별 AP**와 mAP50-95. 평균 하나 뒤에 0점인 클래스가 숨을 수 있음 |
| 3 데이터 | 면적·비율·**그룹 중복**·해시 감사. 빈 라벨은 누락이 아니라 정상 기록 | **그룹 분할**. 이미지 단위로 나누면 같은 장면이 train·val에 섞임 |
| 4 학습 | seed·optimizer를 고정하고 **API와 CLI를 같은 설정**으로 기록 | **imgsz 하나만** 바꿔 파라미터 수·시간·지표 비교 |
| 5 검증 | **클래스별** P·R·AP로 먼저 볼 오류 이미지 정하기 | **best와 last**를 같은 val에서 비교. 마지막 epoch이 최선이 아닐 수 있음 |
| 6 추론 | **conf 후보 3개**로 TP·FP·FN 비교. 올리면 FP↓, FN↑ | 오류를 **유형별 분류**(중복·배경 FP·놓침 등)하고 우선 개선안 작성 |
| 7 추적 | **Tracker 2종**을 독립 인스턴스로 비교, 처리량과 측정 범위 기록 | 모듈형 프로젝트로 나누고 **모델 해시·처리 수**를 기록 |
| 8 재현 | **짝이** README만 보고 재실행 | **새 프로세스에서 복원**해 행 수·좌표·확률을 허용오차로 대조 |

## 전체 파라미터 지도 — "무엇을 정하는 값인가"로 묶기

### A. 좌표와 라벨 — "숫자 4개가 무엇을 뜻하나"
| 파라미터 | 오늘의 값 | 한 줄 의미 |
|---|---|---|
| xyxy | `[x1, y1, x2, y2]` 픽셀 | 왼쪽 위·오른쪽 아래. 그리기·IoU 계산용 |
| cxcywh | `[cx, cy, w, h]` 픽셀 | 중심과 크기. Ultralytics `boxes.xywh` 형식 |
| 정규화 좌표 | 0~1 (x÷W, y÷H) | 해상도와 무관한 라벨 저장 형식 |
| 라벨 한 줄 | `class_id cx cy w h` | 객체 하나 = 한 줄, 숫자 5개 |
| 빈 라벨 파일 | 객체 0개 | 누락이 아니라 "없음"을 적은 정상 기록 |
| 색 순서 | BGR | OpenCV는 파랑·초록·빨강 순서 |

### B. 채점 기준 — "맞았다는 기준은 무엇인가"
| 파라미터 | 오늘의 값 | 한 줄 의미 |
|---|---|---|
| 평가 IoU | 0.5 | 예측과 정답이 이만큼 겹쳐야 같은 객체 |
| 1:1 매칭 | 점수 높은 예측부터 | 한 정답에는 하나만 TP, 나머지는 FP |
| Precision | TP ÷ (TP + FP) | 탐지한 것 중 맞은 비율 |
| Recall | TP ÷ (TP + FN) | 실제 객체 중 찾은 비율 |
| AP | 클래스 하나의 P–R 곡선 요약 | conf 하나의 Precision과 다르다 |
| mAP50 / mAP50-95 | IoU 0.5 / 0.5~0.95 평균 | 뒤쪽이 위치 정확도에 더 엄격 |

### C. 데이터 계약 — "데이터를 믿을 수 있나"
| 파라미터 | 오늘의 값 | 한 줄 의미 |
|---|---|---|
| dataset.yaml | path · train · val · names | 데이터와 모델을 잇는 계약서 |
| names | 0 square, 1 circle, 2 triangle | class_id ↔ 이름 |
| group_id | 같은 장면 묶음 | 한 split에만 둔다 |
| sha256 | 파일 해시 | 같은 파일 중복 검사 |
| Negative image | 객체 없는 이미지 | 거짓 탐지를 줄이는 학습 데이터 |
| test | 학습·선택에 안 씀 | 마지막 확인용 |

### D. 학습과 검증 — "어떻게 학습시키고 무엇을 남기나"
| 파라미터 | 오늘의 값 | 한 줄 의미 |
|---|---|---|
| model | `yolo26n.yaml` / `best.pt` | 구조만 / 학습된 가중치까지 |
| epochs | 1(점검) · 60(학습) | 전체 train 반복 횟수 |
| imgsz | 160 | 입력 크기. 격자 크기와 작은 객체·속도·메모리를 함께 바꾼다 |
| batch | 4 | 한 번에 넣는 이미지 수 |
| device · workers | cpu · 0 | 실행 장치 · 데이터 로딩 프로세스 |
| seed | 42 | 초기화·증강 순서 재현 |
| best.pt / last.pt | 검증 기준 최고 / 마지막 | 추론 기본 후보는 best |

### E. 추론 — "후보를 어떻게 거르고 결과를 어떻게 읽나"
| 파라미터 | 오늘의 값 | 한 줄 의미 |
|---|---|---|
| 후보 수 | 420 (입력 160×128) | 격자 20×16 + 10×8 + 5×4. 칸마다 후보 하나 |
| conf | 0.25 (val은 0.001) | 이 점수 이하 후보 버림 |
| iou | 0.7 | NMS에서 이만큼 겹친 중복 후보 제거 |
| stream | True(영상) | 결과를 한 장씩 생성, 메모리 절약 |
| `boxes.xyxy` / `xyxyn` | 픽셀 / 정규화 | 같은 박스의 다른 표기 |
| `boxes.cls` · `conf` | 클래스 ID · 점수 | 이름은 `names[int(cls)]` |

### F. 추적 — "ID를 어떻게 잇나"
| 파라미터 | 오늘의 값 | 한 줄 의미 |
|---|---|---|
| tracker | bytetrack.yaml / botsort.yaml | 프레임 사이 연결 방법 |
| persist | 같은 영상 안에서만 True | 호출 사이 Tracker 상태 유지 |
| `boxes.id` | Track ID | 객체 종류가 아닌 "같은 객체" 번호 |
| `boxes.is_track` | ID가 붙은 프레임인지 | ID를 읽기 전에 확인 |
| track_buffer | 30 프레임 | 사라진 객체를 기다리는 길이 |
| 속도 측정 범위 | 추론만 / 입출력 포함 | 어디부터 어디까지 쟀는지 함께 적는다 |

## 참고
- 모델 실측은 응용 데이터 train 36장으로 `yolo26n.yaml`을 60 epoch 학습한 모델로 쟀습니다(imgsz 160, CPU). 실습의 `data/demo.pt`와 숫자가 다를 수 있습니다.
