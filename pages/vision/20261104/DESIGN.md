## 2. 1판 → 2판에서 바뀐 이유

- **1판 (표 형식 사다리):** 상자마다 의미·손잡이·이유·확인 칸을 글로 채운 표였다. 사용자 피드백은 이랬다.
  - "중간 상자층이 너무 길어 가독성이 나쁘다."
  - "지도에 텍스트가 많다."
  - "이미지를 처리하는 것이니 직관적으로 보여 달라."
  - "질문 목록 없이 지도 하나로 이해되어야 한다."
- **판단:** 기준 교재도 같은 사진 한 장을 여러 처리에 통과시킨 결과를 나란히 보여 주는 그림으로 설명한다(Sz 그림 3.11, 3.18, 3.22, 3.13, UDL 그림 9.13). 그래서 그 방식을 따랐다.
- **2판:** 합성 사진 한 장에 실제 OpenCV 함수를 적용한 결과를 썸네일로 이어 붙였다.
  - 상자마다 글은 "왜" 한 줄, 함수 한 줄, 출력 한 줄, 비교 그림 이름표만 둔다.
- **백업:** 1판은 scratchpad `d13_index_v1.html`, `d13_v1.pdf`에 있다.

## 3. 그림 데이터

- **사진:** `make_images.py`로 만든 합성 사진 1장(320×240, BGR)이다. 강의 p.2의 가상 사례(제품 외관 검사)에 맞췄다. 들어 있는 요소는 다음과 같다.
  - 어두운 바탕 위 주황 제품
  - 큰 흠집 1개(타원)
  - 제품 위 4×4 핀홀 5개: Closing으로 메워질 것
  - 바탕의 5×5 흰 먼지 8개: Opening으로 지워질 것
  - 고른 잡음 σ=14
- **크기를 정한 근거:** 먼지·핀홀 크기는 실제 처리로 골랐다(`tune` 실험).
  - 먼지 5×5칸: 이진화 후 남고(덩어리 9개 = 제품 1 + 먼지 8), Opening 후 사라짐(덩어리 1개). Median 5에서도 사라짐.
  - 핀홀 4×4칸: 이진화 후 남고(검은 구멍 5개 + 흠집), Closing 후 메워짐.
- **처리 흐름:**
  - 본 흐름(p.52 순서): Gray → resize `(160,120)` INTER_AREA → GaussianBlur `(5,5),0` → threshold 128 → Opening → Closing(3×3)
  - 결과: `findContours(RETR_CCOMP)`로 찾은 안쪽 구멍 중 면적 20 이상인 것을 흠집 후보로 표시한다(1곳).
- **실제 값:** 확대 칸 (64,52)은 BGR `[52,136,214]`, Gray 150이다. `ret = 128.0`이다. Canny(70,150) Edge 칸 수는 원본 크기에서 Blur 없이 1,996, Blur 후 915다.
- **버전:** OpenCV 4.14.0(`opencv-python-headless<5`)에서 만들었다. 강의 기준인 OpenCV 4.x와 같다. 그림은 PNG로 `index.html` 안에 넣어서 HTML 파일 하나로 열린다.

## 5. 레이아웃

- **머리말:** 질문 배지 + 한 문장 + 범례. 범례 내용은 보는 곳(자기 칸만 / 주변 칸까지 / 다른 자리에서), "왜?", Q 표시다.
- **입력:** 원본 사진 → 확대한 칸 격자 → 칸 하나의 숫자 B·G·R. 옆에 `img.shape`와 세 줄 사실을 둔다.
- **처리:** 상자 카드 6장을 화살표로 잇는다(Gray · resize · Blur · Threshold · Morphology · 결과).
  - 카드 행 순서는 머리(이름 · 교시 · 보는 곳) → 왜? → 결과 썸네일 → 함수 → 출력 → 손잡이를 바꾸면(비교 그림 2장) → Q번호다.
  - 카드들은 CSS subgrid로 행을 공유해 가로로 같은 칸끼리 맞는다.
  - Blur 아래로 갈림길 Canny 카드를 둔다("경계 선만 필요하면").
  - 그 옆에 "결과는 어디로 가나"를 둔다. ① 규칙 판단, ② 모델 입력 + Kernel = CNN 합성곱이다.
- **갈래:** 영상(입력 Frame 4장 → 위 상자들 → 출력 Frame 4장)과 증강(원본 · 좌우 반전 · 10° 회전 · 밝기 +30 · b→d ✕)을 나란히 둔다.
- **확인:** 한 줄로 형식 · 시간 · 개수 → 다시 읽어 대조한다.
- **부록 질문 목록:** 1판의 질문 23개를 그대로 지도 아래에 둔다. 머리에 "지도로 이해됐다면 건너뛰어도 됩니다"를 단다.
  - 지도의 Q번호를 누르면 설명 창으로 열린다.
- **좁은 화면:** 68rem 이하에서 카드 2열, 40rem 이하에서 1열로 바꾼다.

## 6. 교재·강의·실습 사이 차이

- **Threshold 경계:** Sz 식 3.44는 `≥`, OpenCV `THRESH_BINARY`는 `>`다. 강의 값은 p.7이 128, p.46이 140이고, 실습은 127이다. 지도는 128을 쓴다.
- **Canny 임계값:** 강의 p.42는 70/150, 기본필수 README는 80/160이다. 지도는 강의 값을 쓴다.
- **영상 저장:** 강의는 mp4v/MP4, 실습은 MJPG/AVI·48Frame·12FPS다. 지도의 "48 ÷ 12 = 4초"는 실습 기준이다.
- **밝기 증강:** 강의 p.69는 `convertScaleAbs`이고, 지도와 실습은 `float + 30 → clip → uint8`이다.
- **Border:** Sz의 clamp·mirror는 OpenCV의 REPLICATE·REFLECT 계열이다. 필터 기본값은 `BORDER_REFLECT_101`, `warpAffine` 기본값은 검은색(`BORDER_CONSTANT`)이다. 회전 그림의 검은 모서리가 바로 이 기본값이다.
- **Morphology 순서:** 지도의 본 흐름은 Opening → Closing이다. 강의 p.52 그림의 마지막 단계는 Closing이고, 기본필수 실습은 Opening만 쓴다.
- **결과 판단 규칙**(안쪽 구멍 면적 20 이상): 강의 범위 밖의 예시 규칙이다. 지도에 "사람이 정한 기준"이라고 적었다.

## 7. 검증 (2026-11-04)

- **수치:** 3절의 값은 `make_images.py`가 출력한 `facts.json` 값을 HTML에 그대로 넣었다.
  - Gray 150 재계산: `0.299×214 + 0.587×136 + 0.114×52 = 149.75`
- **화면:** Playwright와 시스템 Chrome으로 375·768·1280·1440px에서 질문을 모두 펼치고 확인했다.
  - 가로 넘침과 스크립트 오류가 없다.
  - 지도의 Q 링크가 모두 질문에 연결된다.
  - 설명 창은 열기와 Esc 닫기가 동작하고, 주소 `#n-fps`로 들어오면 그 질문이 펼쳐진다.
- **PDF:** `Day13_개념지도.pdf`. 1440px 폭 세로 한 장(1080 × 1641pt)이다.
  - 질문 부록, 지도의 Q번호, 바닥글의 질문별 근거·비유 안내를 뺀 **지도만의 배포본**이다(사용자 요청, 2026-11-04). `html.pdf.nonotes` 클래스로 숨긴다.
  - PDF 안에 링크는 없다(pypdf로 확인). 웹 `index.html`에는 질문 부록이 그대로 있다.
