## 2. 보여 주는 방식

같은 두 테이블을 카드마다 다시 그리고, SQL이 고르거나 바꾸는 칸만 표시한다.

- 분류마다 색이 정해져 있다(learning·environment·reference). `category_id`와 분류 이름에 같은 색 칩을 쓰고, 색만으로 구분되지 않게 글자를 함께 둔다.
- 행 표시는 네 가지다: 남는 행(진하게) · 빠지는 행(흐리게) · 추가(초록) · 삭제(취소선). 수정은 이전 값 → 새 값으로 보여 준다. 표시마다 "남음·추가·수정·삭제" 글자를 붙인다.
- 카드 한 장에는 세 가지만 둔다: SQL 2~8줄 · 표시한 테이블 · 핵심 한두 줄.

## 3. 화면 순서

| 구역 | 내용 |
|---|---|
| 큰 그림 | 어제·오늘·내일 띠 / 실제 테이블 두 개(6행)와 FK 관계 / SQL 지도 네 줄(조회·변경·테이블 정의·트랜잭션, 누르면 카드로 이동) |
| 조회 | SELECT · JOIN · LEFT JOIN · GROUP BY 카드 4장 |
| 변경 | INSERT · UPDATE · DELETE 카드 3장 (각각 처음 3행에서 실행) |
| 테이블 정의 | CREATE TABLE 카드: knowledge 정의, 열·자료형·제약조건 배지 표, 거부되는 예 5개(✕ + 제약조건 이름) |
| 트랜잭션 | 새 분류 api + 지식 INSERT(CHECK 위반)를 두 칸으로 비교: BEGIN 없이 → api만 남음 / BEGIN으로 묶고 ROLLBACK → 둘 다 없음. 내일 `db.commit()`·`db.rollback()`과 연결 |
| 종합 | PRIMARY KEY · FOREIGN KEY · 제약조건 · 트랜잭션이 각각 무엇을 하고 어디에 쓰이는지 네 줄 |
| 더 알아보기 (접힘) | HAVING, SUM·MIN·MAX, LIKE, NULL과 빈 문자열, INDEX·EXPLAIN, 번호 건너뜀, SQL과 HTTP |
| 바닥 | PostgreSQL 가이드 링크, 실행 환경 |

## 4. 실측

- `capture/capture.py`가 수업 준비 SQL로 새 S0 DB를 만들고, 카드의 SQL을 하나씩 실행해 `capture/capture.json`에 기록한다. 변경은 트랜잭션 안에서 실행한 뒤 취소해서, 카드마다 처음 3행에서 시작한다.
- Auto commit 비교는 새 DB에서 실제로 확정되는 것을 확인한다.
- 보여 주는 CREATE TABLE은 빈 스키마에 실제로 만들어 문법을 확인한다. 거부되는 예 5개는 실행해서 거부되는지 확인한다.
- `build.py`는 기록만 읽어 `index.html`을 만들고, 거부 종류·행 수를 `assert`로 대조한다.
- 실행 환경: PostgreSQL 17.10 (수업은 18 계열. 이 SQL들의 결과는 버전에 따라 달라지지 않음)

## 5. 다시 만드는 명령

```bash
cd capture && PGHOST=localhost PGPORT=55432 PGUSER=postgres uv run capture.py   # PostgreSQL 필요
cd .. && python3 build.py
```
