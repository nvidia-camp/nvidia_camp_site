## 오늘을 한 문장으로

> **브라우저(/docs)가 보낸 요청을 FastAPI가 Method·Path로 처리 함수에 연결하고, 함수 매개변수에 적은 자료형·모델로 입력을 검증한 뒤, 지식 항목을 JSON 파일에서 읽고·추가하고·바꾸고·지우며, 결과를 상태코드(200·201·204·404·422)와 JSON으로 돌려준다. 성공 여부는 응답이 아니라 다시 조회한 값과 파일, 서버 재시작 후의 상태로 확인한다.**

```text
 클라이언트          FastAPI                        처리 함수               JSON 파일
 (/docs)    ──▶  Method + Path로 함수 찾기   ──▶  지식 찾기·변경   ──▶  data/knowledge.json
            요청  매개변수 선언으로 입력 검증         (CRUD)            읽기·저장
                  └ 실패하면 함수 실행 전 422
            ◀──  상태코드 + JSON 응답  ◀──────────────────────────────────
 오늘 범위: 지식 CRUD + 파일 저장.  이후: PostgreSQL → RAG 검색·생성 → Agent 도구 연결
```

구조는 강의 PDF p.14 그림(한 번의 요청은 어디를 거치는가)과 p.3 전체 시스템 그림을 따릅니다.

**꼭 알고 갈 개념 세 가지** (이 그림 하나로 설명하고, 다른 구역은 이 그림을 가리킨다)
1. **요청 하나 = Method + Path (+ Query, Body), 응답 하나 = 상태코드 + Body.** `GET /api/knowledge/2`는 "2번 지식을 읽는다", `POST /api/knowledge` + Body는 "새 지식을 만든다"이다. 공식 문서는 Method·Path와 처리 함수를 묶은 단위를 *path operation*이라 부른다(강의의 Route).
2. **FastAPI는 함수 매개변수를 보고 입력 위치와 검증을 정한다.** Path에 있는 이름이면 Path, `int`·`str` 같은 단일 값이면 Query, Pydantic 모델이면 Body(공식 문서 Request Body). 자료형이나 규칙이 맞지 않으면 함수가 실행되기 전에 422로 거절한다.
3. **응답과 저장은 별개다.** `status_code=201`은 선언일 뿐 저장을 하지 않는다. 저장은 `write_data()`가 한다. 그래서 확인은 응답 + 재조회 + 파일 + 재시작으로 한다.

**하루 내내 지키는 약속 세 가지**
1. **응답만 믿지 않는다.** POST·PUT·DELETE 뒤에는 같은 ID를 GET으로 다시 읽고 `knowledge.json`을 연다
2. **ID는 서버가 `next_id`로 발급하고 줄이지 않는다.** 목록 위치(index)와 ID는 다른 숫자다
3. **실패한 요청은 파일을 바꾸지 않는다.** 404·422 뒤에 항목 수와 `next_id`가 그대로인지 본다

| 교시 | 핵심 질문 | 핵심 개념 |

| 4 | 수정은 추가와 무엇이 다른가? | PUT(같은 ID의 내용을 통째로 교체, 세 필드 모두 필요), index vs ID(목록 위치 ≠ 지식 번호), PATCH(바꿀 필드만 보내는 부분 수정, 오늘은 참고) |
| 5 | 지운 것과 실패한 것을 무엇으로 확인하나? | 204(성공, 본문 없음), `raise HTTPException`(오류 응답은 return이 아니라 raise), 405(경로는 있지만 Method가 없음), 실패 시 보존(404·422 뒤 파일 그대로) |
| 6 | 같은 기능을 왜 여러 파일로 나누나? | Schema(데이터 모양), Router(HTTP 약속), Repository(읽기·저장), APIRouter(작은 FastAPI, prefix로 경로 묶음), Template(같은 데이터를 HTML로) |
| 7 | 다섯 요청의 약속이 하나로 맞는가? | API 계약(Method·Path·입력·정상 응답·오류 응답 표), 끝까지 추적(생성 → 조회 → 수정 → 재시작 → 삭제 → 재시작), JSON 파일의 한계(동시 변경·관계·트랜잭션 → DB) |
| 8 | 서버를 껐다 켜도 B 수정·C 삭제가 남는가? | A 유지·B 수정·C 삭제, 실제 재시작(Ctrl+C 후 같은 명령, /docs 새로고침은 재시작 아님), N → N+3 → N+2 |

## 공식 튜토리얼로 따라가기

강의 슬라이드 하단의 `참고 S01 · S04` 번호가 가리키는 공식 문서를 교시 순서로 정리했습니다. 처음 보는 개념은 이 순서대로 문서를 열면 됩니다.

| 교시 | 공식 문서 | 문서에서 볼 곳 | 오늘 코드에서 |
|---|---|---|---|
| 1 | [First Steps](https://fastapi.tiangolo.com/tutorial/first-steps/) | path operation decorator와 function, `/docs` | `app = FastAPI(...)`, `@app.get("/health")` |
| 2 | [Path Parameters](https://fastapi.tiangolo.com/tutorial/path-params/) | 자료형을 선언하면 변환·검증, `foo` → 422 예시 | `knowledge_id: int` |
| 2 | [Query Parameters](https://fastapi.tiangolo.com/tutorial/query-params/) | 기본값이 `None`이면 선택 Query | `category: str \| None = None` |
| 3 | [Request Body](https://fastapi.tiangolo.com/tutorial/body/) | 매개변수 위치를 정하는 규칙 3가지 | `payload: KnowledgeWrite` |
| 3 | [Body - Fields](https://fastapi.tiangolo.com/tutorial/body-fields/) | `Field`는 `fastapi`가 아니라 `pydantic`에서 import | `Field(min_length=1, max_length=80)` |
| 3 | [Response Model](https://fastapi.tiangolo.com/tutorial/response-model/) | 반환 데이터를 모델로 검증·필터링 | `response_model=Knowledge` |
| 3·5 | [Response Status Code](https://fastapi.tiangolo.com/tutorial/response-status-code/) | `status_code`는 데코레이터의 인자, 204는 본문 없음 | `status_code=201`, `status_code=204` |
| 2·5 | [Handling Errors](https://fastapi.tiangolo.com/tutorial/handling-errors/) | `HTTPException`은 return이 아니라 raise | `raise HTTPException(status_code=404, ...)` |
| 4 | [Body - Updates](https://fastapi.tiangolo.com/tutorial/body-updates/) | PUT은 교체, 부분 수정은 PATCH + `exclude_unset` | `update_knowledge` |
| 6 | [Bigger Applications](https://fastapi.tiangolo.com/tutorial/bigger-applications/) | `APIRouter`, `prefix`, `include_router` | 심화 `app/` 구조 |
| 7·8 | [Testing](https://fastapi.tiangolo.com/tutorial/testing/) | `TestClient` + pytest | 심화 `tests/` |
| 2 | [Python json](https://docs.python.org/3/library/json.html) · [pathlib](https://docs.python.org/3/library/pathlib.html) | `json.load`·`json.dump`, `Path(__file__)` | `read_data`, `write_data` |

**강의 용어와 공식 문서 용어**
- Route(강의) = *path operation*(문서): Method + Path + 처리 함수
- `@app.get(...)` 줄 = *path operation decorator*
- 처리 함수, View·Handler(강의) = *path operation function*

**문서와 강의가 다른 곳 한 군데**
- 서버 실행 명령. 공식 문서는 `fastapi dev`를 쓰고, 강의는 `python -m uvicorn main:app --reload`를 씁니다. `fastapi dev`도 안에서 Uvicorn을 띄웁니다. 다만 `fastapi[standard]`를 설치해야 쓸 수 있고, 강의 `requirements.txt`의 `fastapi`만으로는 명령이 없습니다(실측). 요약에는 강의 명령을 씁니다.

## 코드로 보는 하루 흐름

오늘 배우는 과정을 **공식 문서의 기본 사용법 그대로**, 초보자가 위에서 아래로 읽으면 이해되도록 쓴 뼈대입니다. 1~5교시가 `main.py` 한 파일에 이어지고, 6교시는 같은 코드를 파일로 나눈 구조, 7·8교시는 이 코드를 실제 서버로 끝까지 추적한 결과입니다. 줄 수를 줄이는 축약 문법(한 줄 `if … else`, `map`, 중첩 호출)은 쓰지 않았고, 함수 인자는 공식 문서의 이름으로 적었습니다(`HTTPException(status_code=..., detail=...)`).

**데이터는 따로 받지 않습니다.** `make_data.py`가 강의 PDF p.22와 같은 시작 지식 3건을 만듭니다. 두 파일을 같은 폴더에 두고 아래 순서로 그대로 실행됩니다.

### 흐름 요약

| 순서 | 하는 일 | 코드에서 일어나는 일 | 교시 |
|---|---|---|---|
| 준비 | 시작 데이터 파일 만들기 | `make_data.py`가 `data/knowledge.json`(지식 3건, `next_id` 4)을 만든다. 파일이 이미 있으면 건드리지 않는다 | – |

| ② | 파일 읽기·저장 | `read_data()`는 파일 → dict, `write_data()`는 임시 파일에 쓴 뒤 교체. 읽기~저장을 `LOCK` 하나로 묶음 | 2 |
| ③ | 목록·상세 조회 | `category` Query로 목록 거르기, `knowledge_id: int` Path로 한 건 찾기, 없으면 `raise` 404 | 2 |

| ⑧ | 끝까지 추적 | 생성 → 조회 → 수정 → 재시작 → 실패 입력 → 삭제 → 재시작 | 7·8 |

```python
# make_data.py — 시작 데이터 파일 만들기 (서버를 켜기 전에 한 번만 실행)
import json
from pathlib import Path

# ── [준비] 시작 지식 3건 ──
start = {
    "next_id": 4,
    "entries": [
        {"id": 1, "title": "가상환경", "category": "setup",
         "content": "프로젝트별 패키지를 분리한다."},
        {"id": 2, "title": "서버 실행", "category": "api",
         "content": "uvicorn으로 개발 서버를 켠다."},
        {"id": 3, "title": "입력 오류", "category": "api",
         "content": "422이면 입력값을 확인한다."},
    ],
}

data_dir = Path(__file__).resolve().parent / "data"
data_dir.mkdir(exist_ok=True)
path = data_dir / "knowledge.json"

# 이미 파일이 있으면 기존 지식을 덮어쓰지 않는다
if path.exists():
    print("이미 있음:", path)
else:
    text = json.dumps(start, ensure_ascii=False, indent=2)
    path.write_text(text, encoding="utf-8")
    print("만듦:", path)
```

**지식 관리 API — `main.py`** (1~5교시)

```python
# main.py — 지식 관리 API
# 실행: python -m uvicorn main:app --reload  →  http://127.0.0.1:8000/docs
import json
from pathlib import Path
from threading import Lock

from fastapi import FastAPI, HTTPException, Response
from pydantic import BaseModel, Field

# ── [1교시] 앱 만들기와 첫 경로 ──
app = FastAPI(title="Knowledge API")


@app.get("/health")
def health():
    return {"status": "ok"}


# ── [2교시] JSON 파일 읽기·저장 ──
BASE = Path(__file__).resolve().parent
DATA = BASE / "data" / "knowledge.json"
LOCK = Lock()


def read_data():
    # 파일이 없거나 깨졌으면 오류를 낸다 (빈 목록으로 덮어쓰지 않는다)
    with DATA.open("r", encoding="utf-8") as f:
        return json.load(f)


def write_data(data):
    # 임시 파일에 다 쓴 다음 원본과 바꾼다
    temp = DATA.with_suffix(".tmp")
    try:
        with temp.open("w", encoding="utf-8") as f:
            json.dump(data, f, ensure_ascii=False, indent=2)
        temp.replace(DATA)
    finally:
        temp.unlink(missing_ok=True)


# ── [2교시] 목록·상세 조회 ──
@app.get("/api/knowledge")
def list_knowledge(category: str | None = None):
    with LOCK:
        data = read_data()
    result = []
    for entry in data["entries"]:
        no_filter = category is None
        same_category = entry["category"] == category
        if no_filter or same_category:
            result.append(entry)
    return result


@app.get("/api/knowledge/{knowledge_id}")
def get_knowledge(knowledge_id: int):
    with LOCK:
        data = read_data()
    for entry in data["entries"]:
        if entry["id"] == knowledge_id:
            return entry
    raise HTTPException(status_code=404, detail="Knowledge not found")


# ── [3교시] 입력 모델과 생성 ──
class KnowledgeWrite(BaseModel):
    title: str = Field(min_length=1, max_length=80)
    content: str = Field(min_length=1, max_length=2000)
    category: str = Field(min_length=1, max_length=30)


class Knowledge(KnowledgeWrite):
    id: int


@app.post("/api/knowledge", status_code=201, response_model=Knowledge)
def create_knowledge(payload: KnowledgeWrite):
    with LOCK:
        data = read_data()
        entry = payload.model_dump()
        entry["id"] = data["next_id"]
        data["entries"].append(entry)
        data["next_id"] += 1
        write_data(data)
    return entry


# ── [4교시] 수정 ──
@app.put("/api/knowledge/{knowledge_id}", response_model=Knowledge)
def update_knowledge(knowledge_id: int, payload: KnowledgeWrite):
    with LOCK:
        data = read_data()
        for i, entry in enumerate(data["entries"]):
            if entry["id"] == knowledge_id:
                updated = payload.model_dump()
                updated["id"] = knowledge_id
                data["entries"][i] = updated
                write_data(data)
                return updated
    raise HTTPException(status_code=404, detail="Knowledge not found")


# ── [5교시] 삭제 ──
@app.delete("/api/knowledge/{knowledge_id}", status_code=204)
def delete_knowledge(knowledge_id: int):
    with LOCK:
        data = read_data()
        for i, entry in enumerate(data["entries"]):
            if entry["id"] == knowledge_id:
                data["entries"].pop(i)
                write_data(data)
                return Response(status_code=204)
    raise HTTPException(status_code=404, detail="Knowledge not found")
```

### 6교시 — 같은 코드를 파일로 나누면

기본필수는 위 구조 그대로 두고 "어느 줄이 HTTP이고 어느 줄이 저장인지"를 설명합니다. 심화는 같은 코드를 역할별 파일로 옮깁니다(공식 문서 Bigger Applications). 동작과 URL은 바뀌지 않습니다.

```text
main.py 한 파일 (위 코드)               심화 구조 (같은 코드를 역할별로)
────────────────────────────            ──────────────────────────────────────────────
[1교시] app, /health            ──▶   app/main.py                     앱 만들기 + app.include_router(router)
[3교시] KnowledgeWrite, Knowledge ──▶  app/schemas.py                  입력·응답의 모양
[2~5교시] @app.get/post/put/delete ─▶ app/routers/knowledge.py        Method·Path·상태코드·404
                                        └ APIRouter(prefix="/api/knowledge")
[2교시] read_data, write_data,  ──▶   app/repositories/json_knowledge.py  읽기·ID 발급·저장
        ID 발급·추가·교체·삭제
실행: python -m uvicorn app.main:app --reload   (프로젝트 최상위 폴더에서)
```

### 7·8교시 — 끝까지 추적한 결과 (실제 서버 재시작)

위 코드를 실제 Uvicorn 서버로 띄우고, 8교시 과제(A 유지·B 수정·C 삭제)를 그대로 수행한 결과입니다. 재시작은 서버 프로세스를 끄고 같은 명령으로 다시 켠 것입니다.

| 단계 | 요청·조작 | 결과 |
|---|---|---|
| 시작 | `GET /api/knowledge` | 200, N = 3 |
| 생성 | A·B·C를 `POST` 3회 | 201 × 3, 받은 ID A=4·B=5·C=6, 목록 6개(N+3) |
| 수정 | B를 `PUT /api/knowledge/5` (세 필드, content만 변경) | 200, ID·개수 그대로 |
| 재시작 1 | 서버 종료 → 재실행 → `GET /api/knowledge/5` | 200, 수정한 본문 그대로 |
| 실패 입력 | `content=""`인 `POST` | 422 `string_too_short`, 파일 바이트 그대로 |
| 삭제 | `DELETE /api/knowledge/6` | 204, 본문 0바이트 |
| 재시작 2 | 서버 종료 → 재실행 → A·B·C 조회 | A 200, B 200(수정 본문), C 404, 목록 5개(N+2) |

### 꼭 알고 갈 함수 — 사용 가이드

| 교시 | 함수 | 용도 | 사용법 | 확인할 점 |
|---|---|---|---|---|
| 1 | `FastAPI()` → `@app.get()`·`@app.post()`·`@app.put()`·`@app.delete()` | 앱을 만들고, Method + Path를 처리 함수에 연결한다(path operation decorator) | `app = FastAPI(title="Knowledge API")` 다음 줄에 `@app.get("/health")`, 그 아래 `def health():` | 실행 명령의 `main:app`은 "main.py 안의 `app` 변수". 등록하지 않은 Method로 보내면 405(실측 `PATCH` → 405) |
| 2 | Path·Query 매개변수 선언 | URL에서 값을 받는다. 경로 `{}` 안에 있는 이름은 Path, 그 밖의 단일 값은 Query | `@app.get("/api/knowledge/{knowledge_id}")` + `def get_knowledge(knowledge_id: int):` / `def list_knowledge(category: str \| None = None):` | 자료형이 곧 검증이다. `/foo` → 422 `int_parsing`, loc `["path", "knowledge_id"]`. 기본값 `None`이면 생략 가능 |
| 3 | `BaseModel` + `Field()` | Body로 받을 JSON의 모양과 규칙(필수·길이)을 정한다 | `class KnowledgeWrite(BaseModel):` 안에 `title: str = Field(min_length=1, max_length=80)` | `Field`는 `pydantic`에서 import한다. 기본값이 없으면 필수 필드. 누락 → `missing`, 빈 문자열 → `string_too_short`, 81자 → `string_too_long`(모두 422) |
| 3 | `payload.model_dump()` | 검증된 모델을 dict로 바꿔 저장용 데이터를 만든다 | `entry = payload.model_dump()` 다음 `entry["id"] = data["next_id"]` | 저장은 하지 않는다. 저장은 `write_data(data)`가 따로 한다 |
| 3 | `status_code=` · `response_model=` (데코레이터 인자) | 성공했을 때의 상태코드와 응답 모양을 정한다 | `@app.post("/api/knowledge", status_code=201, response_model=Knowledge)` | 함수가 아니라 데코레이터에 쓴다. 선언일 뿐 저장·사실성을 보장하지 않는다(실측: 지워도 저장은 됨, 상태만 200) |
| 2·5 | `HTTPException()` | 대상이 없을 때 오류 응답을 보낸다 | `raise HTTPException(status_code=404, detail="Knowledge not found")` | `return`이 아니라 `raise`. return하면 200으로 나간다(실측). 응답 Body는 `{"detail": "Knowledge not found"}` |
| 5 | `Response(status_code=204)` | 삭제 성공을 본문 없이 알린다 | 목록에서 `pop(i)` → `write_data(data)` → `return Response(status_code=204)` | 204에는 Body가 없다. 확인은 같은 ID의 GET 404와 파일로 한다. 클라이언트에서 빈 204에 `.json()`을 부르지 않는다 |
| 6 | `APIRouter()` → `app.include_router()` | 관련 경로를 한 파일로 묶어 main에서 연결한다 | `router = APIRouter(prefix="/api/knowledge", tags=["knowledge"])` → `@router.post("")` → main에서 `app.include_router(router)` | prefix + 경로가 합쳐져 `/api/knowledge`. `tags`는 /docs의 묶음 이름이며 권한 설정이 아니다. prefix 끝에 `/`를 붙이지 않는다 |
| 7·8 | `TestClient()` | 서버를 켜지 않고 앱에 요청을 보내 자동으로 확인한다(심화) | `client = TestClient(app)` → `r = client.delete("/api/knowledge/9999")` → `assert r.status_code == 404` | `httpx` 설치가 필요하다. 실제 파일 대신 `tmp_path` 임시 파일을 쓴다. 서버 재시작 확인은 대신하지 못한다 |

### 코드 속 파라미터 — 어디를 고치면 무엇이 달라지나

모든 결과는 위 핵심 코드 사본에서 **한 곳만 바꿔** 실제로 실행한 값입니다. 시작 상태는 지식 3건(ID 1·2·3), `next_id` 4입니다.

**보내는 요청만 바꾸기** — 코드는 그대로, /docs에서 보내는 값만 바꾼다

| 교시 | 파라미터 | 위 코드 | 고친 코드 | 결과 | 조건·데이터 | 꼭 기억 |
|---|---|---|---|---|---|---|
| 2 | Path 값 | `GET /api/knowledge/2` | `GET /api/knowledge/foo` | 200 → 422 `int_parsing`, loc `["path", "knowledge_id"]`. 함수가 실행되기 전에 거절 | 시작 3건 | 매개변수의 자료형 선언이 곧 입력 검증이다 |
| 2 | Path 값 | `GET /api/knowledge/2` | `GET /api/knowledge/9999` | 200 → 404 `{"detail": "Knowledge not found"}` | 시작 3건 |  |
| 2 | Query 값 | `?category=api` | `?category=none` | 2건 → 200 + `[]` | 시작 3건 | 결과 0건은 오류가 아니라 200 + 빈 목록이다 |
| 3 | Body 필드 | `{"title": …, "content": …, "category": …}` | `title` 빼기 | 201 → 422 `missing`, loc `["body", "title"]`. 항목 4개·`next_id` 5 그대로 | 생성 1회 뒤 상태 |  |
| 3 | Body 값 | `"content": "Python 3.10 이상을 사용한다."` | `"content": ""` | 201 → 422 `string_too_short`(최소 1자). 파일 바이트 그대로 | 생성 1회 뒤 상태 |  |
| 3 | Body 값 | `"title": "실습 환경 안내"` | `"title": "가" × 81자` | 201 → 422 `string_too_long`(최대 80자) | 생성 1회 뒤 상태 |  |
| 3 | Body 문법 | 올바른 JSON | `{"title": "a",}` (끝 쉼표) | 422 `json_invalid` "Illegal trailing comma" | 생성 1회 뒤 상태 |  |
| 4 | Body 필드 | PUT에 세 필드 | `category` 빼기 | 200 → 422 `missing`, 기존 항목 그대로 | ID 4 수정 | PUT은 교체라 세 필드가 모두 필요하다 |
| 4 | Path 값 | `PUT /api/knowledge/4` | `PUT /api/knowledge/9999` | 200 → 404, 새 항목이 생기지 않음(4개 그대로) | 정상 Body |  |
| 5 | 반복 요청 | `DELETE /api/knowledge/4` | 같은 요청 한 번 더 | 204(본문 0바이트) → 404 | ID 4 생성 뒤 |  |

**선언 하나만 바꾸기** — 함수 안은 그대로, 매개변수·데코레이터만 바꾼다

| 교시 | 파라미터 | 위 코드 | 고친 코드 | 결과 | 조건·데이터 | 꼭 기억 |
|---|---|---|---|---|---|---|
| 2 | Path 자료형 | `knowledge_id: int` | `knowledge_id: str` | `GET /2`: 200 → 404, `GET /foo`: 422 → 404 | 시작 3건 | 문자열 `"2"`는 정수 `2`와 같지 않아 못 찾는다. 자료형이 비교까지 바꾼다 |
| 3 | 상태코드 | `@app.post("/api/knowledge", status_code=201, …)` | `status_code=201,` 지우기 | 201 → 200. 저장은 그대로 됨(ID 4 생성, `next_id` 5) | 정상 Body | 상태코드는 선언일 뿐, 저장과 따로 움직인다 |

**코드 한 줄 바꾸기** — 저장·ID·교체·오류를 처리하는 줄 하나를 바꾼다

| 교시 | 파라미터 | 위 코드 | 고친 코드 | 결과 | 조건·데이터 | 꼭 기억 |
|---|---|---|---|---|---|---|
| 3 | 저장 호출 | `write_data(data)` | 줄 지우기 | 응답은 201·`id` 4 그대로 → `GET /api/knowledge/4` 404, 파일은 3건 그대로 | 정상 Body | 성공 응답이 와도 저장 줄이 없으면 아무것도 남지 않는다 |
| 3 | ID 발급 | `entry["id"] = data["next_id"]` | `entry["id"] = len(data["entries"]) + 1` | ID 2 삭제 뒤 생성: 새 ID 4 → 3, 파일 ID `[1, 3, 3]`, `GET /3`은 옛 "입력 오류" | ID 2 삭제 뒤 생성 1회 | 목록 길이로 ID를 만들면 삭제 후 기존 ID와 겹친다 |
| 4 | 교체 | `data["entries"][i] = updated` | `data["entries"].append(updated)` | PUT 응답은 200·"새 본문"으로 같음 → 파일 ID `[1, 2, 3, 3]`(4개), `GET /3`은 옛 본문 | `PUT /3` 1회 | 응답만 보면 정상처럼 보인다. 재조회와 항목 수로 확인한다 |
| 2 | 오류 처리 | `raise HTTPException(status_code=404, …)` | `return HTTPException(status_code=404, …)` | `GET /9999`: 404 → 200 + `{"status_code": 404, "detail": …, "headers": null}` | `get_knowledge`만 변경 | 오류는 raise해야 오류 상태코드로 나간다 |
