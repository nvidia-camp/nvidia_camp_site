### 2-2. 네 역할 (1교시 · p.3, p.10, p.21, p.97)

| 역할 | 맡는 것 | 하지 않는 것 |
|---|---|---|
| 저장 · FastAPI + PostgreSQL | 요청·응답, 원본 지식 보관 | 문장 의미 생성 |

## 3. 오늘의 통합 뷰 (페이지의 중심)

강의 p.4(확대)와 p.5(흐름) 두 그림을 하나로 합친다. 아래 세부 구역은 모두 이 그림의 한 칸을 펼친 것이다.

### 3-1. 가로축 · 문장이 지나가는 길 (p.5, p.20, p.97)

```text
 [입력]                         [표현]        [모델 내부]       [출력]
 문장 → Tokenizer → Token ID → Embedding → Transformer Block × N → LM Head → Logit → Softmax → 다음 Token
  2교시                          3교시          4·5교시                     6교시
                                                                                          │
   ◀──────────────────────────── 선택한 Token을 문장 끝에 붙여 다시 입력 (EOS까지 반복) ────┘
```

### 3-2. 세로축 · Transformer 칸을 열면 (p.4, p.6, p.7)

```text
Transformer 층 반복     Block 1 → Block 2 → … → Block N        shape (B, T, D) 유지
 └ Block 하나          Self-Attention → Residual/Norm → FFN → Residual/Norm
    └ Self-Attention   Token 사이의 정보를 섞는다
       └ Q · K · V     Score = QKᵀ/√dₖ → Mask → Softmax → Weight × V
```

### 3-3. 같은 그림, 두 가지 사용법 (p.9, p.70~71)

| | 학습 Training | 추론 Inference |
|---|---|---|
| 그림의 끝 | Logit과 정답 Token으로 Loss 계산 | Logit에서 다음 Token 선택 |
| 그다음 | `backward()` → `optimizer.step()` | 선택한 Token을 붙여 반복 |
| 가중치 | 바뀐다 | 고정 |

### 3-4. 처음 나오는 이름

| 이름 | 한 줄 뜻 |
|---|---|
| Token | 모델이 다루는 글자 조각. 단어와 같지 않다 |
| Token ID | Token을 어휘표(Vocabulary)에서 찾은 번호. 크기에 의미가 없다 |
| Embedding | Token ID를 계산할 수 있는 숫자 벡터로 바꾼 것 |
| Hidden State | Transformer를 지나며 문맥이 섞인 Token 벡터 |
| Attention | 각 Token이 다른 Token의 정보를 얼마나 가져올지 정하는 계산 |
| Logit | 다음 Token 후보마다 매긴 점수. 아직 확률이 아니다 |
| Softmax | 점수를 합이 1인 확률로 바꾸는 함수 |
| Context Window | 한 요청에서 모델이 볼 수 있는 Token 수의 한도 |

## 4. 세부 · 통합 뷰의 칸을 차례로

구역마다 **핵심 한 줄 → 그림 또는 표 → 강의 숫자 예시**. 구역 머리는 번호 띠. 교시 표시와 PDF 쪽은 작은 글씨로 붙인다.

### 구역 1 · 입력: Token과 Context (2교시)

| 주제 | 보여 줄 것 | 쪽 |
|---|---|---|
| Tokenizer | 원문 → Token 조각 → Token ID. Token ≠ 단어, 모델마다 Token 수가 다르다 | p.27~28 |
| Special Token | BOS·EOS·PAD·Chat Role. 개수에 포함될 수 있다 | p.29~30 |
| Padding·Truncation | 길이를 맞추는 PAD, 길이를 자르는 Truncation(요약이 아니라 손실) | p.31, p.34 |
| Context Window | System·대화·검색 근거·**출력까지** 한 예산. 영구 Memory가 아니다 | p.32 |
| Token 예산 | 300 + 1,200 + 2,000 + 150 + 출력 예약 850 표 | p.33 |
| 왜 세는가 | 계산량·지연 · 비용(입출력 Token 과금) · 품질(잡음·잘림) | p.35 |

### 구역 2 · 표현: Embedding과 위치 (3교시 + 4교시 p.55)

| 주제 | 보여 줄 것 | 쪽 |
|---|---|---|
| Embedding | Token ID → Embedding 행 조회 → d차원 벡터 | p.38 |
| shape 읽기 | `()` → `(4,)` → `(5, 4)` → `(2, 5, 4)` | p.39 |
| Token vs Sentence Embedding | 모델 입력용 여러 벡터 / 문장 전체 하나의 벡터(검색용, 11/18) | p.40 |
| Position | 순서를 벡터 계산에 반영. 방식은 Sinusoidal·Learned·RoPE | p.41, p.55 |
| Cosine 유사도 | 방향 비교 1 · 0 · −1. 2D 지도(실습 안내 A·B는 가깝고 주문 FAQ는 멀다) | p.42~44 |

### 구역 3 · 모델 내부 ①: Transformer Block (4교시)

| 주제 | 보여 줄 것 | 쪽 |
|---|---|---|
| Block의 네 부품 | Self-Attention(섞기) · FFN(각자 변환) · Residual(`x + f(x)`) · LayerNorm(스케일 조절) | p.50, p.52 |
| Attention vs FFN | Token 사이를 섞는가 / 위치마다 따로 변환하는가 | p.53 |
| shape 따라가기 | `(2, 5)` → `(2, 5, 8)` → `(2, 5, 8)` → `(2, 5, 8)` → logits `(2, 5, 100)` | p.51, p.54 |
| 세 가지 모델 구조 | Encoder(양방향) · Decoder-only(Causal) · Encoder–Decoder | p.48~49 |

### 구역 4 · 모델 내부 ②: Self-Attention (5교시)

| 주제 | 보여 줄 것 | 쪽 |
|---|---|---|
| Q·K·V | 찾는 것 · 가진 특징 · 가져올 값. 실제로는 `X`에 학습 행렬을 곱한 결과 | p.7, p.60 |
| 계산 다섯 단계 | `Q @ K.T` → `/ √d_k` → `+ Mask` → `softmax` → `@ V` | p.59, p.61 |
| 숫자로 한 번 | 3×3 Weight 표 `[1,0,0] / [.33,.67,0] / [.25,.25,.50]`, t3 행 × V → `[0.75, 0.75]` | p.8, p.62~63 |
| Multi-Head | Head별로 다른 참고 패턴, 결합 후 Projection | p.65 |
| 해석의 한계 | Weight가 크다고 판단의 유일한 이유는 아니다 | p.66~67 |

### 구역 5 · 출력: Logit에서 다음 Token까지 (6교시)

| 주제 | 보여 줄 것 | 쪽 |
|---|---|---|
| Logit | 마지막 Hidden State → LM Head → 어휘 전체 점수. 확률이 아니다 | p.73 |
| Softmax·Temperature | 같은 Logit `[2, 1, 0]`에 0.5 · 1.0 · 2.0 → 낮으면 날카롭고 높으면 완만 | p.74 |
| Decoding | Greedy · Temperature · Top-k · Top-p 표 | p.75 |
| 반복 생성 | Prompt → Logit → 선택 → 붙이기 → EOS까지. Prefill과 Decode 구분 | p.76 |
| KV Cache | 이전 Key/Value 재사용. 장기 Memory가 아니다 | p.77 |
| 학습 후 활용 | Prompting(가중치 그대로) · Instruction Tuning · Preference Alignment | p.72 |

## 5. 헷갈리기 쉬운 짝

강의의 퀴즈(p.14·26·37·47·58·69·79·87)와 오류 사례(p.94)를 하루 단위로 모은 표. 페이지 끝에서 하루를 다시 꿰는 역할.

| 이것은 | 이것과 다르다 | 구역 |
|---|---|---|
| Token | 단어 | 1 |
| Token ID (정수 번호) | Embedding (연속 벡터) | 1·2 |
| Truncation (자르기) | 요약 | 1 |
| Padding Mask (빈칸 무시) | Causal Mask (미래 가리기) | 1·4 |
| Score (Softmax 전) | Weight (Softmax 후, 행 합 1) | 4 |
| Logit (점수) | 확률 | 5 |
| Context Window·KV Cache | 장기 Memory | 1·5 |
| 학습 (가중치 변경) | 추론 (가중치 고정) · RAG 근거 전달 | 3-3·5 |
| Cosine이 높다 | 답이 맞다 | 2·6 |
| 형식 검증 (Schema·Pydantic) | 사실 검증 | 6 |
| Attention Weight | 모델 판단의 전체 근거 | 4 |
