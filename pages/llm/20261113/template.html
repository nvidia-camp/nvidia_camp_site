전체

가운데 LLM이 판단과 문장 생성을 맡으며 세 가지 일이 모두 이곳을 거친다. LLM이 고른 행동도 실제 실행은 권한 확인을 통과한 Tool API에서만 일어난다. LLM은 외부 API로 부르는 모델이라 점선 테두리로 따로 표시했다.

글 요약·정리

사용자 → FastAPI → Context 조립 → LLM → 답

모델 혼자 할 수 있는 일이다. 결과는 내용이 맞는지와 JSON 같은 형식이 맞는지를 본다.

사내 규정에 근거한 답변

PostgreSQL → 벡터 인덱스 → Retriever → Context 조립 → LLM → 답

모델은 학습이 끝난 뒤에 바뀐 사내 문서를 모른다. Retriever가 찾은 문서 발췌를 질문과 함께 Context에 넣어 보내고 답에 붙은 출처가 최신 문서인지 확인한다.

시스템 상태 조회·변경

FastAPI → Agent ⇄ LLM, Agent → 권한 확인 → Tool API → 실행 결과 → Agent

Agent는 LLM에게 다음 행동을 묻고 그 행동을 권한 확인에 넘긴다. 허용된 Tool API만 실행되며 결과는 다시 Agent를 거쳐 LLM에 들어가 다음 판단으로 이어진다. 이 고리가 끝날 때까지 실행 기록이 남는다.

  • 1Context 조립 · 질문의 의도나 필요한 조건이 빠진 채 모델에 들어간다
  • 2Retriever · 관련 문서를 못 찾거나 옛 버전을 가져온다
  • 3LLM · 근거에 없는 내용을 그럴듯하게 지어낸다 (Hallucination)
  • 4생성한 답 · JSON 모양은 맞는데 내용이 틀린다

질문과 문서를 같은 모델로 벡터 하나씩({{E5_DIM}}차원) 만든 뒤 방향을 비교한다. Retriever는 Cosine이 가장 큰 A를 골라 Context에 넣는다. 그림의 선 길이에는 의미가 없고 각도만 본다.

Cosine은 두 벡터의 방향이 얼마나 같은지 재는 값이다. 방향이 같으면 1, 직각이면 0, 반대면 −1이 나온다(p.42). 점수가 높은 문서라도 그 내용이 최신이고 맞는지는 아래 답 검사에서 따로 본다.

오른쪽 값은 다국어 문장 임베딩 모델 multilingual-e5-small로 측정했다(강의 p.45의 all-MiniLM-L6-v2는 영어 전용). 이 모델은 점수가 대체로 높게 나와서 절대값보다 순서를 본다. 문서 A·B·C는 강의 일일프로젝트의 지식 문장(p.89).

그림 3에서 만든 벡터 묶음 (T, D)가 Block을 N번 지나는 동안 같은 모양을 유지한다. T는 그림 2에서 센 Token 수다.

Block 안의 표는 행이 지금 위치, 열이 참고하는 위치다. t3는 앞의 t1·t2와 자기 자신을 0.25 · 0.25 · 0.50 비율로 섞어 새 벡터 [0.75, 0.75]가 되고 아직 오지 않은 칸은 Causal Mask 때문에 0으로 남는다.

LM Head가 낸 Logit [2.0, 1.0, 0.0]은 후보별 점수이며 Softmax를 거쳐 합이 1인 확률이 된다. 고른 Token을 문장 끝에 붙이면 맨 앞부터 계산이 다시 돈다.

학습할 때만 Logit과 정답 Token으로 Loss를 구해 backward()·optimizer.step()으로 가중치를 고친다. 추론 때는 가중치를 고정해 둔다.

Attention 표와 확률은 p.62·p.74 코드를 실행한 값이다.

더 알아보기 · 이 페이지에서 줄인 내용
Special Token
시작·끝·빈칸·대화 역할(system·user·assistant)을 표시하는 Token. 모양과 번호는 모델마다 다르다(p.30).
Sentence Embedding · Cosine
문장 하나를 벡터 하나로 만들고 두 벡터의 방향이 얼마나 비슷한지 잰다. 11/18 Vector DB 검색의 바탕이 된다(p.40~45).
Position
같은 Token도 놓인 순서에 따라 다르게 계산되도록 위치 정보를 벡터에 더한다. Sinusoidal · Learned · RoPE(p.41, p.55).
Encoder · Decoder
Encoder는 문장 앞뒤를 모두 보고 표현을 만들고, 생성용 Decoder는 앞쪽만 보며 다음 Token을 고른다(p.49).
Multi-Head Attention
Head마다 참고 비율을 따로 계산해서 합친다(p.65).
Decoding
Greedy · Temperature · Top-k · Top-p. 확률에서 실제로 Token 하나를 고르는 규칙이다(p.74~75).
KV Cache
앞 Token의 Key·Value를 저장해 두었다가 다음 Token을 계산할 때 다시 쓴다. 한 번 생성하는 동안에만 쓰는 저장소다(p.77).
Prompting · Fine-tuning
입력만 바꿔 모델을 쓰는 방법과 가중치를 더 학습시키는 방법(p.72).
