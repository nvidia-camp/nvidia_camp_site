# Day21 (2026.11.16) 구성안 · Prompt·Context Engineering

## 방향

- 중심은 코드가 아니라 **Prompt가 무엇인지, 엔지니어가 Prompt를 어떻게 다루는지**다. 실험(A/B, Development·Holdout)은 거기서 파생된 개념이다.
- 새 그림을 만들지 않는다. **강사 자료 핵심요약 6구역의 그림을 같은 모양으로 쓴다**(수강생이 계속 본 그림).
- 개념을 카드로 나열하지 않는다. **흐름 그림 위에 개념을 얹고, 개념 사이의 구분(≠)을 이음새로** 쓴다.
- 코드·함수 가이드·파라미터 실측은 이 날에는 쓰지 않는다. 모델 호출 없이 샘플로 검사기를 확인하는 수업이라 코드 암기의 가치가 작다.

## 구성

각 구역은 번호 구역으로 나누고, 머리에 "전체 흐름에서 어디인가"를 표시한다. 전문 용어는 한글과 원어(Prompt, Context, Output Contract, Validation, Retry, Evaluation 등)를 함께 적는다.

1. 전체 흐름 한 장: 질문 → Context → Prompt → LLM 응답 → 자동 검사 → 근거 대조, 아래 띠 "A/B 평가 → 입력 개선". 노드를 누르면 해당 구역으로 이동. 지시·문맥·검증 세 줄.
2. Prompt (1·2교시): 여섯 요소, 고정 템플릿 + 요청별 값, Zero/Few-shot. 구분: 지시 ≠ 참고 자료, 예제 ≠ 학습, 예제 ID ≠ 이번 질문의 출처 ID.
3. Context (3·4교시): 지식 101~103 중 [101] 선택, 답변 가능/정보 부족 두 질문, Context Window. 구분: DB에 있는 것 ≠ 이번에 전달한 것, 정보 부족 ≠ 실패.
4. 출력 계약과 검증 (6교시): 네 필드 JSON, 문법 → 구조 → 규칙(자동) → 내용(사람), 반례. 구분: 형식을 요청 ≠ 형식을 검사, 출처 ID 존재 ≠ 본문이 답을 뒷받침.
5. 재시도 (7교시): 세 갈래(정상 / 형식 오류 / 규칙 위반), 최초 1회 + 형식 수정 1회 = 최대 2회. 구분: 형식 오류(고친다) ≠ 규칙 오류(멈춘다), 첫 응답 ≠ 수정 후 결과.
6. A/B 평가 (2·5·8교시): 공통 조건 고정, A/B, D/H. 구분: A/B(Prompt 버전) ≠ D/H(질문 묶음), manual_chat ≠ fixture, 미실행 ≠ 미평가.
