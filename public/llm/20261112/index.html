실습 1 · FastAPI

빈칸 하나를 채우고 저장한 뒤 /docs에서 눌러 보기를 반복합니다.

진행 순서

  1. VS Code로 01_FastAPI 폴더를 열고 터미널에서 설치합니다. 
    python -m pip install -r requirements-check.txt
  2. 서버를 켜고 http://127.0.0.1:8000/docs를 엽니다. 저장할 때마다 서버가 자동으로 다시 켜집니다. 
    python -m uvicorn main:app --reload
  3. /docs에서 GET /api/knowledge → Try it out → Execute. 빈칸 상태라 500이 나옵니다. 서버 터미널에 어느 빈칸인지 나옵니다. 
    NotImplementedError: B-API-01: 주석 요구사항을 완성하세요.
  4. main.py에서 그 빈칸의 raise NotImplementedError(…) 줄을 지우고 TODO 주석대로 코드를 씁니다. 저장 후 다시 Execute → 200.
  5. 6개를 모두 채우면 다른 터미널에서 채점합니다. 
    python check_api.py
    빈칸이 남았으면 
    검사 실패: NotImplementedError: B-API-02
    모두 맞으면 
    검사 통과: 40개 확인

빈칸과 확인 방법

빈칸채울 내용/docs에서 확인
01entries를 id 오름차순으로 반환GET 목록 → 200, 3개
02id가 같은 항목을 반환GET 2 → 200, “서버 실행”
03요청 Body를 dict로 바꾸고 next_id를 id로POST + requests/POST_valid.json → 201, id 4. knowledge.json에도 추가됨
04목록에 추가, next_id +1, 저장
05찾은 위치의 항목을 교체하고 저장PUT 4 + PUT_valid.json → 200
06찾은 위치의 항목 하나만 삭제하고 저장DELETE 4 → 204

POST를 여러 번 누르면 id가 5, 6…으로 늘어납니다. 처음부터 다시 하려면 서버를 끄고 python reset_data.py --confirm을 실행합니다.

실습 2A · DB 구축

빈 DB day19_build_b에 두 테이블을 만듭니다.

진행 순서

  1. pgAdmin에서 Databases 우클릭 → Create → Database로 day19_build_b와 day19_crud_b를 만듭니다. 파일 맨 위의 안전장치가 DB 이름을 확인하므로 이름을 정확히 씁니다.
  2. day19_build_b 우클릭 → Query Tool → 폴더 아이콘으로 A_구축/build.sql을 엽니다.
  3. 빈칸 그대로 실행(F5)해 보면 남은 빈칸 이름이 오류에 나옵니다. 
    ERROR:  syntax error at or near "__TODO_B_DDL_01__"
    오류가 나면 ROLLBACK;만 선택해서 실행한 뒤 고칩니다.
  4. 스키마명세서.md를 보며 빈칸 4개를 채우고 전체 실행 → COMMIT. Schemas → public → Tables를 새로고침하면 categories, knowledge가 보입니다.
  5. check_structure.sql, check_insert.sql을 차례로 열어 실행하고 결과를 확인합니다.

C01부터는 __NEW_ID__를 C01 INSERT 결과의 id로 바꿔 넣습니다. 처음 한 번이면 4입니다. 빈칸이 아니라 실행 결과를 넣는 자리입니다.

U01과 U02: 같은 UPDATE, 끝만 다름

U01 · ROLLBACK

BEGIN;
UPDATE public.knowledge
SET content='복습 자료와 예제 코드를 함께 확인합니다.'
WHERE id=4 RETURNING id, content;
ROLLBACK;
SELECT id, content FROM public.knowledge WHERE id=4;
  • UPDATE 직후“복습 자료와 예제 코드를 함께 확인합니다.”
  • ROLLBACK 후“복습 자료는 개인 폴더에서 확인합니다.”

수정이 취소됩니다

U02 · COMMIT

BEGIN;
UPDATE public.knowledge
SET content='복습 자료와 예제 코드를 함께 확인합니다.'
WHERE id=4 RETURNING id, content;
COMMIT;
SELECT id, content FROM public.knowledge WHERE id=4;
  • UPDATE 직후“복습 자료와 예제 코드를 함께 확인합니다.”
  • COMMIT 후“복습 자료와 예제 코드를 함께 확인합니다.”

수정이 확정됩니다

errors.sql: 규칙이 막는지 확인

B_CRUD/errors.sql

오류가 나는 것이 정상입니다. 오류 구간과 바로 뒤의 RECOVER 구간(ROLLBACK)을 차례로 선택해서 실행합니다.

구간시도막는 규칙RECOVER 후
E01본문이 빈 문자열인 INSERTknowledge_content_length (CHECK)지식 3행 그대로
E02없는 분류 999999로 INSERTknowledge_category_fk (FOREIGN KEY)지식 3행 그대로

자주 막히는 곳

  • __NEW_ID__를 그대로 실행column "__new_id__" does not existC01 INSERT 결과의 id(처음이면 4)로 바꿔서 실행합니다.
  • C01을 블록째 실행해서 새 id를 못 봄화면에 개수(4)만 보임INSERT … RETURNING만 선택해서 실행하면 id가 보입니다. 이미 지났다면 SELECT id, title FROM public.knowledge ORDER BY id;로 “보충 학습”의 id를 확인합니다.
  • 오류 뒤 아무것도 실행되지 않음current transaction is abortedDB 이름 옆 아이콘이 ❗로 바뀐 상태입니다. ROLLBACK; 한 줄만 선택해서 실행하면 풀립니다. 블록 전체를 다시 실행하면 ROLLBACK까지 가지 못합니다.
  • tasks.sql 빈칸 오류가 엉뚱한 곳을 가리킴syntax error at or near "id"빈칸 바로 다음 단어를 가리킵니다. 그 앞의 __TODO_…__를 채웁니다.
