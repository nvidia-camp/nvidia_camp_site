11월 20일 DB 이어 쓰기

기존 report_agent_lab의 데이터와 벡터를 읽기 전용으로 사용합니다. 오늘은 새 Python 프로젝트에서 시작합니다. DB 생성·시드·재색인은 건너뜁니다.

실습 준비 파일

DB 점검 SQL Postman Collection Postman Environment 제출용 검증표

수강생용 실습 자료와 민준튜터 완주 안내서 v2는 상단 Slack 게시물에서 받으세요.

실습 전 확인

  1. Basic·Intermediate·Advanced 중 하나를 선택하고 해당 프로젝트 루트를 VS Code에서 엽니다.
  2. 기존 CUDA PyTorch 환경에서 GPU와 패키지를 확인합니다. .env에 DB 접속 정보와 Tool Calling 및 네이티브 구조화 출력을 지원하는 수업 모델을 설정합니다.
  3. pgAdmin에서 report_agent_lab에 연결해 점검 SQL을 실행합니다. 6종 카테고리와 유효한 벡터를 확인하고, 실제 존재하는 ID와 존재하지 않는 ID를 테스트에 지정합니다.

구현과 완료 확인

  1. API 뼈대와 DB 상태 조회를 붙인 뒤 CUDA E5 → pgvector → Document → Cross-Encoder → Runnable RAG 순서로 점검합니다.
  2. rag_search와 lookup_status를 create_agent에 연결합니다. 복합 질문에서 각 도구의 실제 호출과 출처가 맞는지 확인합니다.
  3. 단계별 테스트 후 pytest·Preflight·Live·Postman으로 검증합니다. Postman은 /health와 무료 요청부터 확인하고, 실제 유료 요청은 비용을 확인해 명시적으로 실행합니다.
  4. 실습 전후 DB 스냅샷을 비교하고 Basic T-01~10, Intermediate T-01~14, Advanced T-01~19 중 해당 결과와 실행 증거를 제출합니다.
