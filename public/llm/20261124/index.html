01

Query Rewrite · Standalone Query

2교시

Query Rewrite는 원래 의도를 보존하면서 질문을 검색하기 좋은 독립 문장으로 바꾸는 작업입니다.

History

Standalone Query

“회의실 예약 취소 방법은?”

검색 전 단계입니다. 대화에 없는 숫자·날짜·조건을 추가하지 않으며 원래 사용자 질문을 보존합니다.

03

Candidate-k · Context-k

4·5교시

Retriever는 먼저 후보를 찾고, Reranker가 그 후보를 재정렬한 뒤 일부만 Context에 포함합니다.

Candidate-k

예: Top-10 검색 후보

Context-k

예: 재정렬 후 Top-3 선택

정답 문서가 후보에 없다면 Reranker로 되살릴 수 없습니다. E5·pgvector의 모델·필터 계약을 유지합니다.

04

Bi-Encoder · Cross-Encoder

5교시

Bi-Encoder는 문장을 따로 Embedding하여 빠른 검색에 쓰고, Cross-Encoder는 질문·문서 쌍을 함께 비교해 관련성 점수를 반환합니다.

1단계

E5 + pgvector로 후보 검색

2단계

Cross-Encoder로 후보 점수화·재정렬

Rerank 점수는 정답 확률이 아닙니다. 로컬 추론은 CUDA GPU가 기본이며, 문서 수·VRAM·Batch에 따라 실행 시간이 달라집니다.

05

LangChain · Service Pipeline

6교시

LangChain은 Prompt·Model·Retriever의 입력·출력을 Runnable로 연결합니다. Day26의 RAG 앞에 Rewrite, 검색 뒤에 Reranker를 추가합니다.

검색용 질문

search_query → Retriever·Reranker

답변용 질문

원래 question → Prompt·Generation

Runnable과 invoke는 흐름을 연결하지만 필터·원문 검증·오류 처리를 자동 보장하지 않습니다.
