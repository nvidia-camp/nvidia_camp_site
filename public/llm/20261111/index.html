조회 Queries

테이블은 그대로 두고 행을 골라 봅니다.

SELECT

조건에 맞는 행 조회

SELECT id, title
FROM knowledge
WHERE category_id = 1
ORDER BY id;
결과 2행
idtitlecategory_id
1실습 파일 보관1남음
2서버 실행2
3질문 작성1남음
  • WHERE에 맞는 행만 남고, ORDER BY 순서로 나옵니다. LIMIT n은 최대 n행입니다.
  • 읽는 순서: FROM → WHERE → SELECT → ORDER BY
JOIN

두 테이블 연결

SELECT k.id, k.title, c.name AS category
FROM knowledge AS k
JOIN categories AS c
  ON c.id = k.category_id
ORDER BY k.id;
결과 3행 · 한 행 = 지식 한 건
idtitlecategory
1실습 파일 보관learning
2서버 실행environment
3질문 작성learning
  • ON의 값이 같은 분류 행을 지식 행 옆에 붙입니다. k·c는 테이블 별칭입니다.
LEFT JOIN

짝이 없는 행도 남기기

SELECT c.name AS category, k.title
FROM categories AS c
LEFT JOIN knowledge AS k
  ON k.category_id = c.id
ORDER BY c.id, k.id;
결과 4행
categorytitle
learning실습 파일 보관
learning질문 작성
environment서버 실행
referenceNULL
  • 왼쪽(categories)의 행은 모두 남고, 짝이 없으면 NULL입니다.
GROUP BY

분류별 집계

SELECT c.name AS category,
       COUNT(k.id) AS knowledge_count
FROM categories AS c
LEFT JOIN knowledge AS k
  ON k.category_id = c.id
GROUP BY c.id, c.name
ORDER BY c.id;
결과 3행 · 한 행 = 분류 하나
categoryknowledge_count
learning2
environment1
reference0
  • 분류마다 한 행으로 묶어 셉니다.
  • COUNT(k.id)는 NULL을 세지 않아 빈 분류가 0입니다. COUNT(*)를 쓰면 reference가 1로 나옵니다.

데이터 조작 DML

각 예시는 처음 3행에서 실행한 결과입니다.

INSERT

행 추가

INSERT INTO knowledge (title, content, category_id)
VALUES ('임시 안내', '한 번만 실행합니다.', 1)
RETURNING id;

UPDATE

행 수정

UPDATE knowledge
SET content = '실행 전에 가상환경을 확인합니다.'
WHERE id = 2;
UPDATE 1 · 바뀐 행 수

1실습 파일은 개인 폴더에 보관합니다.

3오류 메시지와 시도한 작업을 함께 적습니다.
  • SET은 바꿀 값, WHERE는 대상입니다. WHERE를 빼면 모든 행이 바뀝니다.

WHERE id = 3;

  • 행만 지우고 테이블은 남습니다. WHERE를 빼면 모든 행이 지워집니다.

데이터 정의 DDL

지금까지 쓴 테이블이 어떻게 정의되어 있는지 봅니다.

CREATE TABLE

테이블 구조와 제약조건

CREATE TABLE knowledge (
  id          BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  title       VARCHAR(80) NOT NULL
              CHECK (char_length(title) BETWEEN 1 AND 80),
  content     TEXT NOT NULL
              CHECK (char_length(content) BETWEEN 1 AND 2000),
  category_id BIGINT NOT NULL
              REFERENCES categories (id) ON DELETE RESTRICT
);
knowledge의 열
열자료형제약조건
idBIGINTPRIMARY KEY IDENTITY
titleVARCHAR(80)NOT NULL CHECK 1~80자
contentTEXTNOT NULL CHECK 1~2,000자
category_idBIGINTNOT NULL FOREIGN KEY → categories.id

categories: id BIGINT PRIMARY KEY IDENTITY · name VARCHAR(30) NOT NULL UNIQUE

이런 INSERT·DELETE는 거부됩니다

  • ✕title에 NULLNOT NULL
  • ✕content에 빈 문자열 ''CHECK
  • ✕category_id에 없는 분류 99FOREIGN KEY
  • ✕분류 learning을 한 번 더 추가UNIQUE
  • ✕지식이 있는 분류 learning 삭제ON DELETE RESTRICT

거부된 뒤에도 knowledge는 3행 그대로

  • 규칙은 CREATE TABLE에서 정하고, DB가 INSERT·UPDATE·DELETE 때마다 검사합니다.
  • 부모 테이블(categories)을 먼저 만듭니다. 관계는 categories 1 : N knowledge입니다.

트랜잭션 Transaction

새 분류 api를 만들고 그 분류에 지식을 넣는데, 두 번째 INSERT가 실패하는 경우입니다.

BEGIN · COMMIT · ROLLBACK

여러 변경을 하나로

BEGIN 없이 (Auto commit)

-- ① 바로 확정
INSERT INTO categories (name) VALUES ('api');
-- ② CHECK 위반으로 실패
INSERT INTO knowledge (title, content, category_id)
VALUES ('API 문서', '', 4);
categories 4행 · 지식 없는 분류 api가 남음
idname
1learning
2environment
3reference
4api남음

BEGIN으로 묶으면

BEGIN;
INSERT INTO categories (name) VALUES ('api');
-- CHECK 위반으로 실패
INSERT INTO knowledge (title, content, category_id)
VALUES ('API 문서', '', 4);
-- 실패했으니 둘 다 취소
ROLLBACK;
categories 3행 · 둘 다 취소
idname
1learning
2environment
3reference
  • 함께 성공해야 하는 변경은 BEGIN으로 묶습니다. 모두 성공하면 COMMIT, 하나라도 실패하면 ROLLBACK합니다.
  • pgAdmin Query Tool은 Auto commit이 기본입니다. BEGIN 없이 실행한 문장은 바로 확정됩니다.
  • 내일 FastAPI 코드에서는 성공하면 db.commit(), 예외가 나면 db.rollback()을 호출합니다.

종합

  • PRIMARY KEY행을 구분합니다WHERE id = 2 — 조회·수정·삭제할 행 하나를 정확히 고름
  • FOREIGN KEY부모에 있는 값만 받습니다JOIN … ON c.id = k.category_id — 조회할 때 그 값으로 연결
  • 제약조건잘못된 값을 거부합니다INSERT·UPDATE가 실패해도 기존 데이터는 그대로
  • 트랜잭션Transaction여러 변경을 하나로 묶습니다COMMIT으로 확정, ROLLBACK으로 취소
더 알아보기
HAVING
GROUP BY … HAVING COUNT(k.id) >= 2 — 묶은 뒤의 그룹을 거릅니다. 묶기 전의 행을 거르는 것은 WHERE입니다.
SUM · MIN · MAX
SUM(char_length(content))처럼 합계·최솟값·최댓값을 구하는 집계 함수입니다.
LIKE
title LIKE '%실습%' — '실습'이 들어간 값. %는 아무 글자 0자 이상입니다.
NULL과 빈 문자열
NULL은 값이 없는 상태, ''는 길이 0인 값입니다. NULL은 IS NULL로 확인합니다.
INDEX · EXPLAIN
CREATE INDEX는 행을 빨리 찾는 구조를 만들고, EXPLAIN은 DB가 행을 찾는 방법을 보여 줍니다. 행이 3개뿐이면 인덱스가 있어도 전부 읽는 Seq Scan이 정상입니다.
번호 건너뜀
ROLLBACK하거나 INSERT가 실패해도 발급된 IDENTITY 번호는 돌아오지 않습니다. 다음 번호를 예상하지 말고 RETURNING으로 확인합니다.
SQL과 HTTP
SQL은 행과 오류만 돌려줍니다. 200·404 같은 상태코드는 API가 정합니다.

pgAdmin·psql 사용법은 PostgreSQL 가이드에 있습니다.
