01

RAG: 검색한 근거로 답변한다

1교시

RAG · Retrieval-Augmented Generation은 질문과 관련된 외부 자료를 검색하고, 선택한 근거를 LLM 입력에 넣어 답변을 생성하는 구성입니다.

Retrieve질문에 맞는 문서
Context실제로 제공할 근거
Generate근거를 이용한 답변
Validate형식·출처·내용 확인

Indexing

문서를 나누고 검색에 필요한 정보와 함께 저장하는 준비 단계입니다.

Query 처리

질문마다 검색·Context 구성·생성·검증을 수행합니다.

검색한 문서는 이번 답변의 입력 근거로 사용합니다. 관련 문서가 있어도 질문의 답이 그 안에 있는지 확인해야 합니다.

02

Document · Retriever

4교시

Document는 본문과 Metadata를 담는 자료형입니다. Retriever는 질문에 필요한 문서를 찾아 반환하는 역할입니다.

page_content

모델의 근거로 사용할 문서 본문

metadata

인용 ID·청크 ID·문서·버전·원문 위치

기존 E5 입력 규칙과 SQL의 현재 버전·Category·준비 상태 조건을 적용한 검색 결과를 Document로 연결합니다.

본문과 출처를 처음부터 함께 전달합니다. Document로 표현하는 것만으로 검색 조건과 근거 검증이 자동 적용되지는 않습니다.

03

Context · Prompt

2·5교시

Context는 이번 답변을 위해 실제로 제공한 근거입니다. ChatPromptTemplate은 질문과 Context 같은 변수를 채워 모델 입력을 구성합니다.

검색 후보Retriever가 반환
선택한 Context본문·실제 포함 ID
Prompt규칙·질문·근거

실제 포함한 근거의 ID를 따로 보관합니다. 길이 제한의 글자 수와 모델의 Token 수를 구분하고, 규칙과 참고 자료를 나누어 구성합니다.

04

LangChain · Runnable · Chain

3·6교시

LangChain은 LLM 애플리케이션의 구성요소를 연결하는 개발 Framework입니다. Runnable은 입력을 받아 작업을 실행하는 단위이며, 순차 Chain은 앞 단계의 출력을 다음 단계에 전달합니다.

입력 dictquestion · context
Prompt모델에 전달할 메시지
Model응답 또는 구조화 결과

|는 연결을 준비하고 invoke()가 실행합니다. 이번 Prompt는 로컬에서 메시지를 만들고 ChatOpenAI는 모델 API를 호출합니다. 공통 호출 방식과 각 단계의 입력 자료형을 구분합니다.

검색 조건·실제 근거·출처 검증은 계속 관리합니다. 반복되는 연결에 공통 기능을 활용하되, 작은 단발성 호출은 직접 코드가 더 단순할 수 있습니다.

05

Citation · Grounding

7교시

Citation은 답변이 가리키는 출처입니다. Grounding은 그 원문이 답변의 주장을 실제로 뒷받침하는 관계입니다.

출처 범위

답변의 ID가 실제 Context에 포함된 ID인지 검사합니다.

근거 내용

답변의 숫자·조건·예외가 원문과 맞는지 대조합니다.

올바른 출처 ID가 정확한 답변을 보장하지는 않습니다. 원문 위치는 검증된 ID를 이용해 서버의 문서 정보에서 연결합니다.

06

Validation · 실패 처리

7·8교시

Structured Output으로 응답 형태를 정하고, 애플리케이션에서 필드·출처·상태 규칙을 검사합니다. 모델 호출의 성공과 검증된 답변의 성공을 구분합니다.

answered

실제 근거에서 답을 찾아 출처와 함께 반환합니다.

insufficient_context

답할 사실이 부족하여 필요한 정보를 안내합니다.

실행 오류

검색·모델 호출·수신·검증 실패를 오류로 처리합니다.

실행 오류를 정보 부족으로 바꾸지 않습니다. 검색 결과·Context·응답·검증 결과를 나누어 확인하면 실패 위치를 찾을 수 있습니다.
