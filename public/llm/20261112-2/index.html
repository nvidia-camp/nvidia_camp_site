2

Session · 요청마다 하나 열고, 끝나면 닫는다

B02

뜻Dependency(Depends)는 “이 함수를 부르기 전에 먼저 준비할 것”이다. get_db()가 Session을 열어 넘겨주고, 응답이 나가면 닫는다.

코드

app/db.py
# Engine: 앱에 하나. DB 연결을 만들고 재사용한다engine = create_engine(settings.database_url, pool_pre_ping=True)# SessionLocal(): 부를 때마다 새 Session을 만든다SessionLocal = sessionmaker(bind=engine, autoflush=False, expire_on_commit=False)def get_db():    # 요청이 들어오면 Session을 열고, 함수에 넘기고, 응답이 나가면 닫는다    with SessionLocal() as db:        yield db

실제 결과

요청 하나에서 Session의 일생
순서일어나는 일
1요청이 들어온다
2with SessionLocal() as db → 이 요청 전용 Session
3yield db → 경로 함수의 db 매개변수로 들어간다
4함수가 끝나고 응답이 나간다
5with가 끝나며 Session을 닫는다

Engine은 앱에 하나, Session은 요청마다 하나. 닫는 것(close)은 저장(commit)이 아니다.

분류 연결 · 이름으로 찾고, 없으면 만든다

B04

뜻add는 Session에 올려 두기, flush는 SQL을 DB에 보내 번호(id) 받기, commit은 확정. 10단계에서 실제로 비교한다.

코드

app/main.py
def get_or_create_category(db, name):    category = db.scalar(select(Category).where(Category.name == name))    if category is None:        category = Category(name=name)        db.add(category)        # INSERT를 보내 id만 받아 둔다. 아직 확정 아님        db.flush()    return category

11

함께 확정 · 새 분류만 남는 반쪽 저장을 막는다

B09

뜻트랜잭션은 함께 성공해야 하는 변경을 한 묶음으로 다루는 것이다. 어제 배운 BEGIN·COMMIT·ROLLBACK이 코드에서는 이 함수다.

코드

app/db.py
@contextmanagerdef transaction(db):    try:        yield        # with 안이 모두 성공하면 한 번에 확정        db.commit()    except Exception:        # 하나라도 실패하면 전부 취소하고 오류를 그대로 올린다        db.rollback()        raise

실제 결과

새 분류를 만든 뒤 지식 저장이 DB 규칙(본문 2,000자 이하)에 걸려 실패하게 했다
저장 방식지식 저장새 분류
분류 먼저 commit → 그다음 지식실패1건 남음 지식 없는 분류
with transaction(db): 안에서 함께실패0건 함께 취소

함께 맞아야 하는 변경은 commit 한 번으로 묶는다. 하나라도 실패하면 rollback으로 전부 취소된다.

Revision 적용 · Alembic

M01M02

뜻Migration은 테이블 구조 변경을 순서 있는 파일(Revision)로 남기고 DB에 적용하는 것이다. Alembic은 SQLAlchemy용 Migration 도구다. 주 DB는 두고 연습 DB day19_migration_b에서만 한다.

코드

from alembic import opimport sqlalchemy as sarevision = "002_source"down_revision = "001_initial"def upgrade() -> None:    op.add_column("knowledge", sa.Column("source", sa.String(120), nullable=True))def downgrade() -> None:    op.drop_column("knowledge", "source")

  1. API 약속(주소·입력·응답)은 오전과 같다. 저장하는 곳만 PostgreSQL로 바뀌었다.

  2. 요청 하나에 Session 하나. 그 안에서 add·flush로 모으고, commit 한 번으로 확정하거나 rollback으로 함께 취소한다.

  3. API는 분류를 이름으로, DB는 번호(FK)로 다룬다. 바꾸는 일은 get_or_create_category와 to_read가 한다.

  4. 테이블 구조를 바꾸는 일은 ORM 코드가 아니라 Migration이 한다. 성공은 응답 id로 DB 행을 다시 찾아 확인한다.

더 알아보기
rollback과 id 번호
rollback해도 이미 발급된 번호는 돌아오지 않는다. 10단계에서 id 6가 지워진 뒤에 7가 나온 것도 같은 이유로, 번호는 건너뛸 수 있다.
DB 오류의 응답
입력 오류(422)·없는 대상(404) 말고도, DB 규칙 충돌은 409, DB 연결 실패는 503, 그 밖의 예상 못 한 오류는 500으로 나누어 응답할 수 있다. basic 완성본은 규칙 충돌만 409로 바꾼다.
refresh() · close()
refresh는 DB 값을 객체에 다시 읽어 오고, close는 Session을 정리한다. 둘 다 저장(commit)이 아니다.
autogenerate · stamp
alembic revision --autogenerate는 ORM과 DB의 차이로 Revision 초안을 만든다. 초안이라 꼭 읽어 봐야 한다. alembic stamp는 이력 표시만 바꾸고 테이블은 바꾸지 않는다.
intermediate · advanced
같은 기능을 파일로 나눈다: schemas.py 분리(intermediate), Router·Service·Repository 구조와 테스트 DB·dependency_overrides로 자동 검증(advanced).
