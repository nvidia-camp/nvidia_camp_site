03

먼저 보여도, 아직 확정할 수는 없습니다

3교시

Streaming은 생성 중 일부를 먼저 받는 방식입니다. SSE(Server-Sent Events)는 서버가 HTTP 연결로 이벤트를 이어 보내는 방식이고, delta는 새 텍스트 조각입니다.

response.created시작
response.output_text.delta부분 미리보기
response.output_text.done텍스트 항목 종료
response.completed전체 응답 확인

완료 응답을 받은 경우

최종 원문과 usage를 확인하고 기존 검증기로 넘깁니다. 근거 검토는 여전히 남습니다.

중단·거절·불완전인 경우

이유를 기록하고 부분 JSON을 정상 답변으로 쓰지 않습니다. 성공 캐시에 저장하지 않습니다.

조각 10개 ≠ 출력 10 Token. 첫 텍스트가 빠름 ≠ 총 완료 시간이 짧음.

04

실패 원인에 따라 다음 행동이 다릅니다

4교시
실패 원인 · 상태 · 남은 예산 확인

설정·권한·한도

401·403·잘못된 요청·할당량 문제는 반복 전송으로 고치지 않습니다. 설정을 확인하고 중단합니다.

일시적 제한

429의 세부 원인을 확인합니다. Retry-After의 최소 대기와 남은 시간·횟수를 지킨 경우에만 다시 보냅니다.

출력·수신 문제

JSON·Schema 형식만 한 번 수정합니다. 거절·출처 오류·정보 부족·timeout은 같은 수정 루프로 보내지 않습니다.

생성 최대 2회 × 생성당 전송 최대 2회전체 실제 전송 최대 4회

이 값은 교안의 정책입니다. SDK 추가 재시도는 0회로 두고 앱에서 관리합니다. Timeout·스트림 중단의 자동 재전송도 하지 않는 수업 정책입니다.

Exponential backoff는 실패가 반복될수록 대기 시간을 늘리는 방식이고, Jitter는 재시도 시점을 분산하는 작은 무작위 지연입니다. 서버의 최소 대기를 줄여서 다시 보내지 않습니다.

06

재사용과 모델 선택은 서로 다른 정책입니다

6·7교시

Response Cache

승인된 최종 답변을 재사용합니다. 유효한 hit이면 새 API 전송을 생략할 수 있습니다.

Prompt Caching

같은 입력 앞부분의 계산을 재사용합니다. 새 API 요청과 새로운 출력 생성은 계속됩니다.

KV Cache

모델의 Key·Value 상태를 재사용합니다. 최종 답변을 보관하는 앱 저장소가 아닙니다.

입력·모델·권한·계약→Cache key→TTL·승인·현재 검사→hit / miss

TTL(Time To Live)은 유효 기간입니다. 같은 질문이어도 지식 본문이나 권한이 바뀌면 예전 답을 재사용하지 않습니다. SHA-256 해시는 식별용이지 암호화가 아닙니다.

modefast / quality
허용 목록권한·기능·예산

Model Routing은 호출 전 모델 선택입니다. fast·quality는 교안의 모드명이지 우열 보장이 아닙니다.
