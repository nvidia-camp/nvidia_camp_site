실패 진단 · Gold Dataset

1·2교시

Gold는 평가 기준으로 검수한 관련 문서 ID와 관련성 등급입니다. 질문별로 Gold를 기록하고 데이터셋 버전을 고정합니다.

Retrieval

관련 문서가 검색 후보에 있었는지, 모델에 전달한 Context에 포함됐는지 차례로 확인합니다.

Generation

Context에 근거가 있을 때 답변이 그 내용을 제대로 사용했는지 확인합니다.

실행 오류와 근거 부족을 구분합니다. 문서로 답할 수 없는 질문도 Gold가 빈 No-answer 사례로 기록합니다.

Recall@k · Precision@k · Hit@k

3교시

Q07 오프라인 결과에서 상위 3개 검색 결과에 Gold 문서 2개 중 1개가 들어 있습니다.

Recall@3

찾은 Gold 수 / 전체 Gold 수
1 / 2 = 0.5

Precision@3

찾은 Gold 수 / 지정한 k
1 / 3 ≈ 0.333

Hit@3

Gold가 하나라도 있으면 1, 없으면 0
1

Gold가 없는 Q06의 Recall은 None으로 기록하고 평균에서 제외합니다.

MRR · nDCG

4교시

MRR은 질문별 첫 관련 문서 순위의 역수(RR)를 평균한 값입니다. nDCG는 관련성 등급과 순위 할인을 반영한 점수(DCG)를 이상적인 순서의 점수(IDCG)로 나눈 값입니다.

MRR@3

Q01은 3위, Q07은 2위에서 처음 적중합니다.
(1/3 + 1/2) / 2 ≈ 0.417

Q01의 nDCG@3

실제 순서의 DCG / 이상적인 순서의 IDCG
3.5 / 7 = 0.5

관련성이 0으로 판정된 문서와 아직 등급을 매기지 않은 문서를 구분합니다.

Generation Evaluation

5교시

Claim은 답변에서 근거를 확인할 수 있는 개별 주장입니다. 답변을 Claim으로 나누고 Context와 대조합니다.

Faithfulness

Context가 뒷받침한 주장 수 / 전체 주장 수
G01은 2 / 3 ≈ 0.667

Relevance

답변이 질문에 직접 응답하는지 확인합니다.

Correctness

답변의 내용이 기준 답변에 비추어 맞는지 확인합니다.

세 기준을 별도로 기록합니다. LLM-as-a-Judge는 모델로 답변을 평가하는 보조 도구이며, 중요한 판정은 사람이 검수합니다.

LangChain 평가 흐름

6교시

Runnable은 입력을 받아 실행하는 LangChain 단위입니다. 평가 Runner는 기존 RAG를 invoke()로 호출하고 질문별 결과를 수집합니다.

Target

실행할 RAG입니다. 질문·Category·대화 기록을 받아 검색 결과, 실제 Context에 포함된 ID, 답변을 반환합니다.

Evaluator

질문 ID로 결과와 Gold·기준 답변을 결합해 질문별 평가 기록을 만듭니다.

Gold와 기준 답변은 Evaluator에서만 사용합니다. Trace는 실행 경로를, 평가 리포트는 기준에 비춘 점수와 판정을 보여 줍니다.

버전 비교 · Quality Gate

7·8교시

같은 질문과 Gold로 설정을 하나씩 바꾸고, 질문별 점수와 실패 위치를 비교합니다. Quality Gate는 Agent Tool 연결 검토에 필요한 1차 통과 조건입니다.

Baseline → Rerank-only

Q01 고정 데이터에서 Recall@3은 1 → 1, nDCG@3는 0.5 → 1.0입니다. 찾은 Gold 수는 같고 순위가 앞당겨졌습니다.

Agent Tool 연결 전

검색 지표·출처·실행 상태를 확인합니다. 실습 결과에서는 사람 검수와 접근 권한 테스트가 남아 검토 조건을 통과하지 못했습니다.

고정 데이터로 계산한 점수는 지표의 동작을 확인하는 데 사용합니다. 실제 모델 품질은 별도로 평가합니다.
