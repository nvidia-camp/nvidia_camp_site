OCR · VLM 문서 AI

오늘 한 문장문서 이미지를 OCR이 읽기 좋게 다듬고(전처리), 단어마다 글자·위치·점수를 받아(OCR), 라벨 옆 값을 원문·좌표와 함께 JSON으로 남긴다(구조화). VLM의 답은 그 원문 근거와 맞을 때만 받아들이고, 맞지 않으면 보류해 사람이 확인한다(Hybrid). 배포는 지원되는 신경망 모델을 ONNX → TensorRT Engine으로 바꿔 대상 장치에서 검증하는 설계다.

꼭 알고 갈
개념

1

OCR은 문자열만 주지 않는다. 단어마다 Text·Box(위치)·Confidence(점수)를 준다. 이 세 가지가 뒤에서 값의 근거가 된다.

2

VLM은 답변 "후보"를 만든다. 이미지와 질문을 함께 이해하지만, 보이지 않는 값을 자연스럽게 지어낼 수 있다(Hallucination). 그래서 원문 근거와 대조한다(Grounding).

3

평가 단위는 서로 다르다. 글자 오류(CER), 필드 정답(Field accuracy), JSON 문법, 근거 일치는 각각 따로 센다. 하나가 좋다고 다른 것이 보장되지 않는다.

import json
import re

import cv2
import jiwer
import numpy as np
import pytesseract
from skimage import data
from transformers import pipeline

importimport

OpenCV는 이미지 처리, pytesseract는 OCR, jiwer는 CER, transformers는 VLM을 맡습니다. 데이터는 scikit-image에 들어 있습니다.

page = data.page()                   # scikit-image 내장 스캔 페이지 (왼쪽이 어둡다)

lines = [
    "INVOICE DOC03",
    "DATE: 2026-11-03",
    "SUPPLIER: ALPHA STUDIO",
    "PRINT 4 3000 12000",
    "FRAME 1 9000 9000",
    "PAPER 3 4000 12000",
    "TOTAL: 33000",
]                                    # 청구서에 쓸 글자 = 정답
invoice = np.full(shape=(480, 700, 3), fill_value=255, dtype=np.uint8)  # 흰 종이
for i, line in enumerate(lines):
    y = 60 + 55 * i                  # 줄마다 55픽셀씩 아래로
    cv2.putText(
        img=invoice,
        text=line,
        org=(40, y),                 # 글자를 쓰기 시작할 위치 (x, y)
        fontFace=cv2.FONT_HERSHEY_SIMPLEX,
        fontScale=1,
        color=(0, 0, 0),             # 검정 (B, G, R)
        thickness=2,
    )

# 네 모서리 순서: 왼쪽 위 → 오른쪽 위 → 오른쪽 아래 → 왼쪽 아래
corners = np.float32([[60, 40], [690, 10], [720, 470], [20, 450]])  # 사진 속 문서
front = np.float32([[0, 0], [699, 0], [699, 479], [0, 479]])        # 정면 문서
tilt = cv2.getPerspectiveTransform(src=front, dst=corners)   # 정면 → 비스듬
photo = cv2.warpPerspective(src=invoice, M=tilt, dsize=(760, 500))  # 비스듬한 사진

준비데이터

왼쪽이 어두운 스캔 페이지를 불러오고, 청구서 7줄을 그린 뒤 일부러 비스듬히 찍은 사진으로 바꿉니다. 그린 글자 lines가 곧 정답입니다.

binary = cv2.adaptiveThreshold(
    src=page,
    maxValue=255,                    # 기준보다 밝은 픽셀 → 흰색(255)
    adaptiveMethod=cv2.ADAPTIVE_THRESH_GAUSSIAN_C,  # 주변의 가중 평균으로 기준
    thresholdType=cv2.THRESH_BINARY,
    blockSize=31,                    # 주변 31×31 칸을 보고 기준을 정한다
    C=11,                            # 그 평균에서 11을 뺀 값이 기준
)
M = cv2.getPerspectiveTransform(src=corners, dst=front)     # 사진 → 정면
warped = cv2.warpPerspective(src=photo, M=M, dsize=(700, 480))  # (너비, 높이)
cv2.imwrite(filename="invoice.png", img=warped)  # 원본 photo는 그대로 둔다

1교시① 전처리

스캔 페이지는 주변 31×31 블록마다 기준을 잡아 흑백으로 나눕니다. 사진은 네 모서리를 정면 네 모서리로 옮겨 펴고, 원본은 그대로 둔 채 보정본을 저장합니다.

text = pytesseract.image_to_string(image=warped, config="--psm 6")
words = pytesseract.image_to_data(
    image=warped,
    config="--psm 6",                # 페이지 모양 가정: 글 블록 하나
    output_type=pytesseract.Output.DATAFRAME,  # 결과를 표(DataFrame)로
)
words = words[words.conf >= 0]          # 단어가 있는 행만 남긴다
review = words[words.conf < 50]         # 점수가 낮은 단어 → 지우지 않고 검토 목록
truth = " ".join(lines)                 # 정답 글자
read = " ".join(text.split())           # OCR 글자 (줄바꿈·공백을 한 칸으로)
score = jiwer.cer(reference=truth, hypothesis=read)  # 글자 오류율 CER

2교시② OCR

image_to_string은 글자 전체, image_to_data는 단어마다 Text·Box·Confidence 표를 줍니다. 낮은 점수는 지우지 않고 검토 목록으로 두고, 정답과 비교해 CER을 잽니다.

match = re.search(
    pattern=r"^TOTAL: (\d+)$",       # "TOTAL: " 뒤의 숫자
    string=text,
    flags=re.MULTILINE,              # ^와 $를 줄마다 적용
)
raw = match.group(1)                    # "33000" : OCR이 읽은 원문
row = words[words.text == raw].iloc[0]  # 그 숫자가 적힌 단어 (첫 번째 행)
total = {
    "raw": raw,
    "value": int(raw),                  # 33000 : 숫자로 바꾼 값
    "conf": float(row.conf),
    "box": [int(row.left), int(row.top), int(row.width), int(row.height)],
}
amounts = re.findall(
    pattern=r"^[A-Z]+ \d+ \d+ (\d+)$",  # 품목 줄의 마지막 숫자 = 금액
    string=text,
    flags=re.MULTILINE,
)
reasons = []
if sum(int(a) for a in amounts) != total["value"]:  # 품목 합 ≠ 합계면 검토
    reasons.append("total_mismatch")

3교시③ 구조화

TOTAL: 줄에서 괄호 안 숫자만 꺼내 원문(raw)과 숫자 값(value)을 함께 남기고, 그 단어의 점수·위치를 근거로 붙입니다. 품목 합이 합계와 다르면 검토 이유를 기록합니다.

pipe = pipeline(
    task="image-text-to-text",
    model="HuggingFaceTB/SmolVLM-256M-Instruct",
)
messages = [
    {"role": "user", "content": [
        {"type": "image", "path": "invoice.png"},
        {"type": "text", "text": "What is the total amount?"},
    ]},
]
out = pipe(
    text=messages,
    max_new_tokens=128,              # 답의 최대 길이 (토큰 수)
    do_sample=False,                 # 같은 입력 → 같은 답
    return_full_text=False,          # 질문은 빼고 답만 받는다
)
answer = out[0]["generated_text"].strip()  # VLM의 답 (문자열)

4교시④ VLM 질문

이미지와 질문을 한 메시지로 묶어 묻습니다. do_sample=False면 같은 입력에 같은 답, return_full_text=False면 새 답만 받습니다.

if answer == total["raw"]:
    final = total["value"]              # 두 결과가 같다 → 채택
else:
    final = None                        # 다르다 → 보류, 사람이 확인

5교시⑤ 결합

VLM 답이 OCR 원문과 같을 때만 채택합니다. 다르면 None(보류)으로 두고 사람이 확인합니다. 보류는 정답으로 세지 않습니다.

6교시⑥ 배포 설계

장비가 필요해 실행하지 않고 공식 명령만 남깁니다. PyTorch → ONNX로 내보내고, 실제로 돌릴 장치에서 TensorRT Engine을 Build합니다.

record = {
    "document_id": "doc03",
    "cer": score,
    "total_amount": total,
    "review_reasons": reasons,
    "vlm_answer": answer,
    "final": final,
}
with open(file="doc03.json", mode="w", encoding="utf-8") as f:
    json.dump(obj=record, fp=f, ensure_ascii=False, indent=2)

CER·합계(원문·값·점수·위치)·검토 이유·VLM 답·최종 값을 한 JSON으로 남깁니다. ensure_ascii=False면 원문 글자가 그대로 저장됩니다.

1교시cv2.adaptiveThreshold

용도
조명·그림자가 고르지 않은 문서를 흑백으로 나눌 때. 조명이 고르면 cv2.threshold(Otsu)로 충분하다
사용법
cv2.adaptiveThreshold(src=gray, maxValue=255, adaptiveMethod=cv2.ADAPTIVE_THRESH_GAUSSIAN_C, thresholdType=cv2.THRESH_BINARY, blockSize=31, C=11). 컬러 이미지는 먼저 cv2.cvtColor(src=img, code=cv2.COLOR_BGR2GRAY)로 Gray로 바꾼다
확인할 점
blockSize(3 이상 홀수)와 C를 몇 개 바꿔 OCR CER이 가장 낮은 값을 고른다

1교시cv2.getPerspectiveTransform → cv2.warpPerspective

용도
비스듬히 찍은 문서를 정면으로 펼 때
사용법
사진 속 네 모서리와 정면 네 모서리를 같은 순서의 np.float32 목록으로 → M = getPerspectiveTransform(src=사진_모서리, dst=정면_모서리) → warpPerspective(src=img, M=M, dsize=(너비, 높이))
확인할 점
결과 이미지를 눈으로 확인한다. 이후 OCR Box는 보정본 기준 좌표다

2교시pytesseract.image_to_string · image_to_data

용도
글자 전체가 필요하면 image_to_string(값 찾기용), 단어별 위치·점수가 필요하면 image_to_data(근거·검토용)
사용법
image_to_data(image=img, config="--psm 6", output_type=pytesseract.Output.DATAFRAME) → text·conf·left·top·width·height 표
확인할 점
PSM은 입력 모양에 맞춘다: 문서 한 장 6, 한 줄 Crop 7, 한 단어 8. conf가 낮은 단어는 지우지 않고 원본에서 눈으로 확인한다

용도

사용법

확인할 점
CER과 필드 정답을 함께 본다. CER이 낮아도 필드가 틀릴 수 있다

3교시re.search → .group(1)

용도
라벨 뒤에 오는 값(합계·날짜)을 꺼낼 때
사용법

확인할 점
못 찾으면 None이 온다. .group() 전에 확인하고, 못 찾은 필드는 검토 목록에 남긴다

4교시pipeline → pipe(text=messages, ...)

용도
이미지에 질문하고 답을 받을 때
사용법
pipe = pipeline(task="image-text-to-text", model=모델ID) → messages에 image 항목과 text 항목을 함께 → pipe(text=messages, max_new_tokens=128, do_sample=False, return_full_text=False) → out[0]["generated_text"]
확인할 점
do_sample=False로 같은 답을 재현하고, max_new_tokens는 답이 잘리지 않을 만큼 준다. 답은 그대로 쓰지 않고 OCR 원문과 대조한다

6교시torch.onnx.export → trtexec

용도
학습한 신경망을 Jetson·GPU에서 빠르게 돌릴 때
사용법
torch.onnx.export(model=model, args=(x,), f="model.onnx") → 원본과 결과 비교 → 대상 장치에서 trtexec --onnx=model.onnx --saveEngine=model.engine
확인할 점
실제로 넣을 batch·입력 크기로 실행해 본다(바뀌는 축은 dynamic_shapes). Engine은 만든 장치·버전에서만 쓴다

용도

확인할 점
numpy 숫자는 int()·float()로 바꿔 넣는다
