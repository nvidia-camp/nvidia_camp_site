매일 루프 · commit · push · pull

status→add→commit→push

PowerShell · Git Bash 공통 · 올리기

처음 한 번 · 원본 연결

PowerShell · Git Bash 공통
git remote add upstream https://github.com/원본계정/저장소.git
git remote -v             # origin · upstream 두 개 보이면 성공

원본의 새 내용 받기 · 전부

PowerShell · Git Bash 공통
git fetch upstream        # 받아만 두기 (내 파일은 그대로)
git merge upstream/main   # 내 main에 합치기
git push                  # 내 GitHub에도 반영

원본의 새 내용 받기 · 특정 폴더만

PowerShell · Git Bash 공통
git fetch upstream
git restore -s upstream/main -- 폴더이름   # 그 폴더만 원본 상태로 가져오기

주의restore는 그 폴더 안의 내 수정을 원본으로 덮어씁니다. 내가 푸는 파일이 없는 새 폴더에만 씁니다.

pull = fetch + merge입니다. 내 GitHub(origin)은 git pull 한 줄, 원본(upstream)은 받아 두고 확인한 뒤 합치도록 나눠 씁니다. merge 메시지 창이 열리면 그대로 저장하고 닫습니다(Vim이면 :wq Enter).

4

브랜치와 머지 · 갈래를 나눴다가 합치기

브랜치(branch)는 커밋에 붙인 이름표입니다. 새 이름표를 만들어 따로 커밋하다가, 다 되면 main에 합칩니다(merge). 색이 채워진 이름표가 지금 있는 브랜치(HEAD)입니다.

PowerShell · Git Bash 공통 · 혼자 쓸 때
git switch -c feature     # 브랜치 만들고 이동
git add .
git commit -m "기능 추가"
git switch main           # main으로 돌아오기
git merge feature         # feature를 main에 합치기
git branch -d feature     # 다 쓴 브랜치 지우기

팀 프로젝트 · Pull Request(PR)

브랜치째 push→GitHub에서 Compare & pull request→리뷰→Merge pull request→내 PC에서 pull

PowerShell · Git Bash 공통
git push -u origin feature   # 브랜치째 GitHub에 올리기
# … GitHub에서 PR 만들고 Merge …
git switch main
git pull                     # 합쳐진 main 받기

충돌(conflict)이 나면

두 브랜치가 같은 줄을 다르게 고치면 Git이 멈추고 파일에 표시를 남깁니다.

CONFLICT (content): Merge conflict in main.py
<<<<<<< HEAD
main line          ← 지금 브랜치(main)의 내용
=======
feature line       ← 합치려는 브랜치(feature)의 내용
>>>>>>> feature

남길 내용만 남기고 표시 줄 세 개를 지웁니다. VS Code에서는 Accept Current · Accept Incoming · Accept Both 버튼으로 고를 수 있습니다. 그다음:

PowerShell · Git Bash 공통
git add main.py
git commit -m "merge feature"
5

되돌리기와 잠시 치우기

상황명령
고친 내용 버리기 (add 전)git restore main.py
add 취소 (고친 내용은 남김)git restore --staged main.py
방금 커밋 메시지 고치기 (push 전)git commit --amend -m "새 메시지"
push한 커밋 되돌리기git revert 커밋ID
pull 전에 내 변경 잠시 치우기git stash → git pull → git stash pop

커밋ID는 git log --oneline 맨 앞 7자리입니다. revert는 기록을 지우지 않고 "되돌리는 커밋"을 새로 만들어서 안전합니다.

주의git reset --hard는 커밋하지 않은 수정을 모두 지웁니다. 되돌릴 수 없으니 쓰기 전에 git status로 꼭 확인합니다.

만들어 주는 사이트

gitignore.io ↗ github/gitignore 템플릿 ↗

gitignore.io에 Python Windows macOS VisualStudioCode를 넣고 Create를 누르면 내용이 나옵니다. 그대로 복사해 프로젝트 맨 위 폴더의 .gitignore에 붙여 넣습니다. GitHub에서 저장소를 만들 때 Add .gitignore → Python을 골라도 됩니다.

명령 한 줄로 받기

curl.exe -L https://www.toptal.com/developers/gitignore/api/python,windows,macos,visualstudiocode -o .gitignore

253줄짜리 .gitignore가 생기고, .env와 .venv가 이미 들어 있습니다.

이미 커밋해 버린 파일

PowerShell · Git Bash 공통

git commit -m "chore: .venv 제외"

API 키를 push했다면커밋을 지우는 것보다 그 키를 먼저 폐기하고 새로 발급합니다. 공개 저장소는 올라가는 즉시 수집됩니다.
