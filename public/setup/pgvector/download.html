DAY 23 · PostgreSQL 18.6 + pgvector 0.8.7 설치 안내

Day 23 | Windows 11 · PostgreSQL 18.6 · pgvector 설치 가이드

강의일: 2026년 11월 18일(수)
목표: 기존 PostgreSQL을 유지하면서 pgvector 0.8.7을 설치하고, pgAdmin SQL과 Python에서 정상 동작을 확인한다.

설치 전 주의: PostgreSQL과 pgAdmin을 다시 설치하거나 삭제하지 않습니다. 기존 데이터베이스와 수업 실습 데이터를 보존합니다. 이번 수업에는 Docker와 WSL을 사용하지 않습니다.

버전 안내: 2026-11-12 PostgreSQL 18.7이 출시되었지만, 이 문서는 수강생의 기존 18.6을 전제로 작성했습니다. 강의 직전 임의 업그레이드는 하지 않습니다. pgvector 서버 확장 버전은 0.8.7을 사용합니다.

A. 이 강의에서 설치하는 것은 무엇인가?

구분 역할 어디에 설치하나?
PostgreSQL 18.6 기존 DB 서버 이미 설치된 C:\Program Files\PostgreSQL\18 (예상 경로)
pgvector 0.8.7 서버 확장 DB에 vector 자료형과 거리 계산·인덱스를 추가 PostgreSQL의 lib, share\extension
Visual Studio C++ Build Tools Windows용 vector.dll을 컴파일 Windows에 설치 (기존 설치 시 재설치 불필요)
Git for Windows pgvector 공식 소스 내려받기 Windows에 설치 (기존 설치 시 재설치 불필요)
Python pgvector 패키지 Python과 PostgreSQL vector 타입 연결 기존 Python 가상환경에 pip install pgvector

핵심: pip install pgvector만으로 PostgreSQL의 vector.dll이 설치되지는 않습니다. 반대로 Windows DLL만 설치하고 CREATE EXTENSION을 실행하지 않으면 해당 DB에서 vector 자료형을 쓸 수 없습니다.

실행 도구를 혼동하지 마세요.

  • pgAdmin → Query Tool: SQL(SELECT, CREATE EXTENSION 등)을 실행합니다.
  • 일반 Windows 명령 프롬프트(CMD): PostgreSQL 설치 파일 경로를 확인합니다.
  • 관리자 권한의 x64 Native Tools Command Prompt: set PGROOT, git clone, nmake를 실행합니다.
  • VS Code → Git Bash(기존 venv 활성화): Python 패키지 설치와 Python 파일 실행에 사용합니다.

1단계. pgAdmin에서 PostgreSQL과 pgvector 기존 상태 확인

  1. Windows 시작 메뉴에서 pgAdmin 4를 실행합니다.
  2. 좌측에서 Servers → 기존 PostgreSQL 서버 → Databases → 강의용 DB를 펼칩니다.
  3. 사용 중인 강의용 DB(예: knowledge_lab)를 마우스 오른쪽 클릭하고 Query Tool을 선택합니다.
  4. 아래 SQL을 붙여넣고 F5로 실행합니다.
-- 서버 버전, 현재 연결한 데이터베이스 및 계정 확인
SELECT version();
SELECT current_database(), current_user, inet_server_port();

-- pgvector 서버 확장 파일이 설치되어 있는지 확인
SELECT name, default_version, installed_version
FROM pg_available_extensions
WHERE name = 'vector';

결과 해석

조회 결과 의미 다음 행동
vector 결과가 0행 PostgreSQL 서버가 pgvector 확장을 아직 발견하지 못함 2~7단계 진행
name=vector, default_version=0.8.7, installed_version=NULL 서버 파일은 있지만 현재 DB에 아직 활성화되지 않음 8단계로 이동
name=vector, installed_version=0.8.7 현재 DB에 설치·활성화 완료 9단계로 이동
installed_version이 다른 버전 이미 다른 버전의 확장이 활성화됨 임의 업데이트하지 말고 강사에게 알림

current_database()가 본인의 강의용 DB가 아닌 경우 먼저 올바른 DB의 Query Tool을 여세요. CREATE EXTENSION은 접속한 DB마다 별도로 적용됩니다.

2단계. PostgreSQL 18.6 프로그램 경로 확인

실행 위치: 일반 CMD (Windows 키 → cmd 검색 → 명령 프롬프트 실행)

"C:\Program Files\PostgreSQL\18\bin\pg_config.exe" --version
"C:\Program Files\PostgreSQL\18\bin\pg_config.exe" --includedir-server
"C:\Program Files\PostgreSQL\18\bin\pg_config.exe" --pkglibdir

예상 확인 내용

  • --version → PostgreSQL 18.6
  • --includedir-server → C:/Program Files/PostgreSQL/18/include/server에 해당하는 경로
  • --pkglibdir → C:/Program Files/PostgreSQL/18/lib에 해당하는 경로

이 명령에서 “파일을 찾을 수 없습니다”가 나오면 PostgreSQL 설치 위치가 다른 것입니다. 파일 탐색기에서 pg_config.exe를 찾아 실제 경로로 대체하세요. 다른 PostgreSQL 버전의 pg_config.exe를 사용하면 안 됩니다.

3단계. Visual Studio C++ Build Tools와 Git 준비

1) C++ 컴파일러 확인·설치

  • Microsoft 공식 사이트 접속: https://visualstudio.microsoft.com/downloads/
  • All downloads → Build Tools for Visual Studio 2026(또는 이미 설치된 Visual Studio 2022의 Build Tools)를 선택합니다.
  • 내려받은 설치 프로그램을 실행합니다. 설치 관리자가 나타나면 Workloads(워크로드) 탭의 Desktop development with C++ / C++를 사용한 데스크톱 개발을 선택합니다.
  • 구성 항목에서 MSVC C++ x64/x86 빌드 도구와 Windows 11 SDK 또는 Windows 10 SDK가 포함되어 있는지 확인합니다.
  • 설치 또는 수정을 완료합니다. 이미 C++ 개발 도구가 갖춰져 있다면 다시 설치하지 않습니다.

VS Code는 Visual Studio Build Tools와 다릅니다. VS Code가 설치되어 있어도 cl.exe와 nmake.exe가 없는 경우가 있습니다.

2) Git 확인·설치

  • 기존 Git이 있다면 그대로 사용합니다. Git Bash 또는 CMD에서 git --version을 실행해 확인하세요.
  • 없다면 공식 사이트 https://git-scm.com/install/win에서 Git for Windows x64를 설치합니다.
  • 설치 후 열어 둔 명령 프롬프트를 닫았다가 다시 열어 PATH를 반영합니다.

회사·교육기관 설치 정책으로 설치가 차단된다면 보안 정책을 우회하지 말고 관리자에게 설치 허용을 요청하세요. 출처 불명의 vector.dll 파일을 다운로드해서 붙여넣지 마세요.

4단계. 빌드 전용 명령 프롬프트를 관리자 권한으로 실행

  1. Windows 키를 누르고 x64 Native Tools Command Prompt를 검색합니다.
  2. 설치된 Visual Studio 버전에 해당하는 항목(예: x64 Native Tools Command Prompt for VS 2026 또는 VS 2022)을 선택합니다.
  3. 마우스 오른쪽 버튼 → 관리자 권한으로 실행을 선택합니다.
  4. 이 창은 CMD 기반 개발자 명령 프롬프트입니다. Python 실습용 Git Bash가 아닙니다.

다음 명령을 한 줄씩 실행합니다.

where cl
where nmake
where git
echo %VSCMD_ARG_TGT_ARCH%

정상: cl.exe, nmake.exe, git.exe 각각의 실행 경로가 표시되고 마지막에는 x64가 출력됩니다. 설치 버전에 따라 폴더 위치는 다를 수 있습니다. 도구가 없거나 x64가 아니면 빌드하지 말고 이 단계부터 수정하세요.

5단계. PGROOT 환경변수와 개발용 파일 확인

실행 위치: 방금 연 관리자 권한 x64 Native Tools Command Prompt

set "PGROOT=C:\Program Files\PostgreSQL\18"
echo %PGROOT%
"%PGROOT%\bin\pg_config.exe" --version
dir "%PGROOT%\include\server\postgres.h"
dir "%PGROOT%\lib\postgres.lib"
  • PGROOT는 bin이나 data가 아닌 PostgreSQL 18의 최상위 설치 폴더입니다.
  • 정상이라면 PostgreSQL 18.6 및 postgres.h, postgres.lib의 파일 정보가 표시됩니다.
  • 실제 PostgreSQL 설치 경로가 다르면 첫 줄의 경로를 바꿉니다.
  • set 명령은 CMD 전용이며 지금 열린 창에서만 유효합니다. 새 창을 열면 다시 실행합니다.
  • 서버 개발 헤더(postgres.h)가 없다면 빌드를 중단하고 PostgreSQL 설치 구성 요소를 확인합니다. 기존 서버를 무조건 삭제하지 마세요.

6단계. pgvector 0.8.7 공식 소스 다운로드

실행 위치: 동일한 관리자 권한 x64 Native Tools Command Prompt

if not exist C:\pgvector-build mkdir C:\pgvector-build
cd /d C:\pgvector-build
git clone --branch v0.8.7 --depth 1 https://github.com/pgvector/pgvector.git
cd pgvector
git describe --tags --exact-match
dir Makefile.win

정상 확인: git describe가 v0.8.7을 출력하고 Makefile.win 파일이 보입니다. C:\pgvector-build는 컴파일 작업용 폴더로, PostgreSQL의 데이터 폴더가 아닙니다.

중요: 이미 C:\pgvector-build\pgvector 폴더가 있을 때 git clone은 실패합니다. 이 경우 폴더를 삭제하거나 덮어쓰지 말고 기존 폴더의 소스·태그를 확인한 뒤 강사 안내를 받으세요. 오늘 강의는 v0.8.7 태그로 고정합니다.

7단계. nmake로 DLL 컴파일 및 서버 확장 파일 설치

여전히 C:\pgvector-build\pgvector 폴더에 있어야 합니다. 먼저 DLL을 만듭니다.

nmake /F Makefile.win
echo %ERRORLEVEL%
dir vector.dll

정상 확인: nmake 실행이 오류 없이 완료되고, 그 직후 echo %ERRORLEVEL%이 0을 표시하며 vector.dll 파일이 생성됩니다. 컴파일러가 표시하는 단순 warning과 실제 오류(fatal error, NMAKE : fatal error)는 구분하세요.

컴파일 성공 후에만 다음 명령으로 PostgreSQL 설치 폴더에 확장 파일을 복사합니다.

nmake /F Makefile.win install
dir "%PGROOT%\lib\vector.dll"
dir "%PGROOT%\share\extension\vector.control"
dir "%PGROOT%\share\extension\vector--*.sql"

정상 확인 파일:

파일 설치 위치 의미
vector.dll C:\Program Files\PostgreSQL\18\lib\ PostgreSQL이 로드할 확장 기능
vector.control C:\Program Files\PostgreSQL\18\share\extension\ 확장 이름과 버전 정보
vector--*.sql C:\Program Files\PostgreSQL\18\share\extension\ DB에서 확장을 생성·업데이트하는 SQL

일반적으로 새 pgvector 확장을 설치할 때 서버 재설치는 필요하지 않습니다. 이미 서버에서 사용 중인 다른 버전의 DLL을 임의로 덮어쓰는 것은 피하세요.

8단계. pgAdmin에서 CREATE EXTENSION vector 실행

  1. 관리자 권한 개발자 명령 프롬프트는 그대로 두거나 닫습니다.
  2. pgAdmin → 강의용 DB(예: knowledge_lab) → Query Tool을 엽니다.
  3. SQL을 실행하기 전에 DB 이름을 다시 확인합니다.
SELECT current_database();

-- 설치 파일 발견 여부 확인
SELECT name, default_version, installed_version
FROM pg_available_extensions
WHERE name = 'vector';

-- 선택한 현재 데이터베이스에서 확장 활성화
CREATE EXTENSION IF NOT EXISTS vector;

-- 현재 DB에 실제 활성화된 버전 확인
SELECT extname, extversion
FROM pg_extension
WHERE extname = 'vector';

정상: extname = vector, extversion = 0.8.7이 조회됩니다. pgAdmin 좌측 데이터베이스의 Extensions 항목을 새로고침하면 vector도 확인할 수 있습니다.

pg_available_extensions가 0행이면 DLL·control 파일이 현재 서버 설치 폴더에 들어갔는지 확인하세요. postgres DB에 활성화했다고 knowledge_lab에서도 자동 활성화되지는 않습니다.

실패한 트랜잭션을 복구해야 한다면

이전에 오류가 발생해 current transaction is aborted가 나오면, 오류가 난 Query Tool에서 아래 명령을 실행하고 실패 원인을 해결한 다음 다시 시도합니다.

ROLLBACK;

정상 실행 중인 트랜잭션에 무작정 ROLLBACK을 하지 말고, 오류로 중단된 트랜잭션일 때만 실행합니다.

9단계. pgvector 거리 계산과 검색 기능 검증

9-1. 벡터 거리 계산(데이터베이스 변경 없음)

실행 위치: pgAdmin Query Tool

-- 코사인 거리(<=>)는 작을수록 가깝습니다.
SELECT
  '[1,0,0]'::vector <=> '[1,0,0]'::vector AS same_direction,
  '[1,0,0]'::vector <=> '[0,1,0]'::vector AS perpendicular,
  '[1,0,0]'::vector <=> '[-1,0,0]'::vector AS opposite_direction;

정상 기대값: same_direction = 0, perpendicular = 1, opposite_direction = 2 (실수 표현에 따른 아주 작은 오차는 가능).

9-2. 임시 테이블에 저장하고 Top-k 조회

아래 SQL은 해당 Query Tool 세션의 임시 테이블만 사용하므로 기존 knowledge 테이블을 변경하지 않습니다.

-- 실습을 다시 실행할 때 현재 세션의 동명 임시 테이블만 제거
DROP TABLE IF EXISTS pg_temp.day23_vector_check;

CREATE TEMP TABLE day23_vector_check (
  id integer PRIMARY KEY,
  label text NOT NULL,
  embedding vector(3) NOT NULL
);

INSERT INTO day23_vector_check (id, label, embedding) VALUES
  (1, '같은 방향', '[1,0,0]'),
  (2, '가까운 방향', '[0.8,0.6,0]'),
  (3, '직각 방향', '[0,1,0]');

SELECT id, label,
       ROUND((embedding <=> '[1,0,0]'::vector)::numeric, 4) AS cosine_distance
FROM day23_vector_check
ORDER BY embedding <=> '[1,0,0]'::vector ASC
LIMIT 3;

정상 기대 결과:

id label cosine_distance
1 같은 방향 0.0000
2 가까운 방향 0.2000
3 직각 방향 1.0000

설치 확인 통과 조건: 확장 버전이 0.8.7이고, 벡터 자료형 생성·INSERT·<=> 검색이 모두 동작해야 합니다. 여기까지는 실제 Embedding 모델이 없어도 점검 가능합니다. 강의에서 사용하는 E5-small의 출력은 384차원이므로 본 실습 테이블에서는 vector(384)를 사용합니다. 이 검증용 3차원 벡터와 혼동하지 마세요.

10-3. verify_pgvector.py 파일 작성

.env와 같은 폴더에 verify_pgvector.py를 만들고 그대로 붙여넣습니다.

"""Windows 11 · PostgreSQL 18 · pgvector 설치 확인용, 데이터 수정 없음."""
from pathlib import Path
import psycopg
from dotenv import dotenv_values
from pgvector import Vector
from pgvector.psycopg import register_vector

# .env는 현재 파이썬 파일과 같은 폴더에서만 읽습니다.
cfg = dotenv_values(Path(__file__).with_name(".env"), interpolate=False)
required = ("PGHOST", "PGPORT", "PGDATABASE", "PGUSER", "PGPASSWORD")
missing = [key for key in required if not cfg.get(key)]
if missing:
    raise RuntimeError(".env 설정 누락: " + ", ".join(missing))

with psycopg.connect(
    host=cfg["PGHOST"],
    port=int(cfg["PGPORT"]),
    dbname=cfg["PGDATABASE"],
    user=cfg["PGUSER"],
    password=cfg["PGPASSWORD"],
) as conn:
    # 중요: PostgreSQL 연결마다 vector 타입을 등록합니다.
    register_vector(conn)

    q = Vector([1.0, 0.0, 0.0])
    database, dimensions, distance = conn.execute(
        "SELECT current_database(), vector_dims(%s::vector), "
        "%s::vector <=> %s::vector",
        (q, q, q),
    ).fetchone()

    assert dimensions == 3, f"잘못된 차원: {dimensions}"
    assert abs(float(distance)) < 1e-6, f"잘못된 거리: {distance}"
    print("연결 DB:", database)
    print("벡터 차원:", dimensions)
    print("자기 자신과의 코사인 거리:", distance)
    print("DB 연결 및 pgvector 확인 완료")

12단계. 최종 설치 완료 체크리스트

  • PostgreSQL 18.6 설치본과 현재 접속 DB를 확인했다.
  • 빌드 전용 CMD에서 where cl, where nmake가 성공했다.
  • PGROOT가 PostgreSQL 18 최상위 폴더를 가리킨다.
  • pgvector 공식 소스 태그가 v0.8.7이다.
  • nmake /F Makefile.win 성공 및 vector.dll 생성 확인.
  • PostgreSQL lib와 share\extension 아래 확장 파일이 존재한다.
  • 강의용 DB의 pg_extension 조회에서 vector 0.8.7이 보인다.
  • SQL에서 코사인 거리 0 · 1 · 2가 조회된다.
  • 임시 테이블 Top-k가 ID 1 → 2 → 3으로 조회된다.
  • 기존 Python 가상환경에서 import pgvector, import psycopg가 된다.
  • python verify_pgvector.py가 DB 연결 및 pgvector 확인 완료를 출력한다.
